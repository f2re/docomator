# 🧩 Docomator

**Автономный корпоративный сервис формирования DOCX/XLSX по шаблонам и типизированным данным — без обязательного доступа в Интернет, с одним общим паролем входа.**

**Текущее состояние:** основной технический контур работает от импорта/экспорта данных и подготовки шаблона до ручного или календарного выпуска, общего хранилища результатов, доставки, диагностики и резервирования. Пространство может содержать людей, аудитории, научные статьи, оборудование и другие типизированные объекты. Целевая Debian/Astra/Office/recovery-приёмка остаётся обязательной до объявления стабильного выпуска.

> [!IMPORTANT]
> Docomator рассчитан на доверенный внутренний контур. В приложение входят по **одному общему паролю**, но персональных учётных записей, ролей и ACL внутри Docomator нет. После входа допущенные пользователи имеют одинаковые возможности. Пространства изолируют связанные данные, но не являются правами доступа. Пароль не заменяет firewall, reverse proxy и HTTPS.

Проверенные сочетания ОС и Office публикуются только в [матрице совместимости](docs/SUPPORT_MATRIX.md). Для безопасного первого прогона используйте [вымышленные примеры](examples/README.md), а не рабочие персональные данные.

## 🎯 Основной рабочий путь

1. войти по общему паролю Docomator;
2. выбрать или создать пространство;
3. импортировать сотрудников/объекты из CSV/XLSX либо добавить вручную;
4. при необходимости выгрузить текущие данные в CSV или XLSX;
5. загрузить и проверить DOCX/XLSX;
6. выбрать изменяемые поля и выполнить пробное заполнение;
7. активировать проверенную версию шаблона;
8. выбрать всех, группу или отдельные объекты;
9. проверить обязательные данные;
10. сформировать персональные или сводные документы;
11. скачать DOCX/XLSX/ZIP либо доставить через SMTP/сетевую папку;
12. при ошибке исправить только проблемные данные и повторить неуспешные единицы.

## 🔐 Общий пароль входа

ADR-0009 вводит один общий password gate без пользователей и ролей.

На **новой установленной системе** UI и предметные API остаются закрытыми, пока оператор локально не задаст пароль:

```bash
sudo bash /opt/docomator/current/app/scripts/offline/set-password.sh
```

Команда:

- спрашивает пароль скрыто и дважды;
- не сохраняет открытый пароль;
- записывает только параметризованный `scrypt`-хэш;
- создаёт новый случайный session secret;
- перезапускает API;
- при смене пароля завершает ранее выданные браузерные сессии.

Сессия браузера хранится в подписанной `HttpOnly`, `SameSite=Strict` cookie с ограниченным сроком жизни. При HTTPS cookie получает `Secure`. Несколько неверных попыток входа включают локальный backoff.

Технические `/healthz` и `/readyz` доступны без пользовательской сессии для systemd/reverse proxy. Остальные рабочие страницы и предметные API закрыты password gate.

В source/dev-тестовом запуске gate отключён только когда переменные `DOCOMATOR_ACCESS_PASSWORD_HASH` и `DOCOMATOR_SESSION_SECRET` вообще не объявлены. Установленный профиль объявляет их пустыми и потому fail-closed остаётся закрытым до настройки пароля.

## 🧱 Пространства и данные

Пространство — жёсткая граница пользовательских данных. Сущности, группы, пользовательские поля, импорт, шаблоны и связанные операции не должны пересекаться между пространствами.

Типы объектов (`person`, `room`, `article` и пользовательские типы) являются общей схемой. Конкретный объект и пользовательское поле принадлежат одному пространству. Кадровый экран — специализированное представление типа `person`.

Подробности: [модель сущностей и импорта](docs/ENTITY_MODEL_AND_IMPORT.md) и [ADR изоляции полей](docs/adr/0008-space-data-isolation.md).

## 📥 Импорт CSV/XLSX

Для сотрудников и произвольных объектов используется сопровождаемый сценарий:

```text
файл → колонки → сопоставление → preview → исправление → импорт → результат
```

Поддерживаются:

- выбор файла и drag&drop;
- CSV UTF-8 и первый рабочий лист XLSX;
- физические номера строк и пустые ячейки без сдвига колонок;
- переносы строк внутри ячейки;
- нормализация регистра и разделение ФИО;
- повторный импорт без лишних дублей;
- структурированные ошибки `code/row/column/propertyKey/rawValue/suggestedAction`;
- подсветка проблемного сопоставления и переход к исправлению;
- сохранение настроек после ошибки.

## 📤 Экспорт CSV/XLSX

В разделах сотрудников и произвольных объектов доступны **«Экспорт CSV»** и **«Экспорт XLSX»**.

Экспорт формируется сервером из явно выбранного пространства и типа объектов:

- включает отображаемое название, состояние и последние значения пользовательских полей;
- использует человеческие заголовки и единицы измерения;
- не выводит UUID и технические ключи;
- имеет устойчивый порядок строк и колонок;
- не читает поля/объекты соседнего пространства;
- нейтрализует пользовательские строки, которые Excel/Calc могли бы выполнить как формулу;
- CSV использует UTF-8 BOM, `;` и CRLF;
- XLSX строится как детерминированный OOXML-пакет с текстовыми ячейками, замороженной первой строкой и фильтром.

Если значение не помещается в ограничения XLSX, сервер не обрезает его молча, а предлагает CSV или разделение выгрузки.

## 🛡️ Шаблоны и документы

До сохранения DOCX/XLSX проверяются ZIP/OOXML, размеры, пути, опасные XML-конструкции, макросы, ActiveX, OLE, подписи и внешние связи. Исходник остаётся неизменяемым объектом по SHA-256.

Поддерживаются:

- выбранный текст внутри DOCX;
- ячейки XLSX;
- несколько полей;
- декларативные форматтеры чисел, дат, дат-времени и `Да`/`Нет`;
- повторяемая строка DOCX;
- повторяемая строка/непрерывный диапазон XLSX;
- персональный и сводный выпуск;
- частичный успех и повтор только ошибок;
- обратное чтение значений после render;
- `_AI_META` для новых XLSX-контрактов;
- необязательный PDF-предпросмотр через локальный LibreOffice.

Неподдерживаемая конструкция должна завершаться конкретным отчётом совместимости, а не повреждённым файлом.

## 📥 Результаты и операции

Все сохраняемые операции и готовые документы видны в **«Результатах»**. Работа продолжается на сервере после перезагрузки страницы или штатного restart worker.

```text
Новый → Просмотрен → Забран
                    ↘ Удалён
```

Скачивание помечает результат как забранный, но не удаляет его. Удаление — отдельное явное действие. Очистка физических объектов без ссылок выполняется только после предварительного плана и подтверждения.

## ⏱️ Расписания и доставка

Поддерживаются однократный, ежедневный и ежемесячный запуск, IANA timezone, сохранённая группа, preflight, защита периода, восстановление после restart и доставка:

- локальный SMTP с TLS и allowlist доменов;
- разрешённая CIFS/NFS-папка, смонтированная средствами ОС;
- проверка mount/sentinel;
- temp-file + fsync + atomic rename;
- повторы временных ошибок без повторного формирования документа.

Готовый документ сохраняется в Docomator даже при ошибке внешней доставки.

## 💾 Резервирование и восстановление

Установка включает ежедневный systemd timer. Копия содержит согласованный SQLite, объектное хранилище и конфигурацию; manifest и SHA-256 проверяются до признания копии годной.

```bash
systemctl list-timers docomator-backup.timer
sudo systemctl start docomator-backup.service
sudo journalctl -u docomator-backup.service
```

Восстановление проверяет manifest и контрольные суммы до замены рабочих данных. Эксплуатационная готовность требует отдельного restore drill на чистой машине.

## 🚀 Локальный запуск из исходников

Требуются Node.js не ниже `24.18.0` и npm 11+:

```bash
node --version
npm --version
npm ci
npm run build
DOCOMATOR_DATA_DIR="$PWD/.tmp/data" npm run migrate
```

API:

```bash
DOCOMATOR_DATA_DIR="$PWD/.tmp/data" npm run start:api
```

Worker во втором терминале:

```bash
DOCOMATOR_DATA_DIR="$PWD/.tmp/data" npm run start:worker
```

Проверка:

```bash
curl --fail http://127.0.0.1:8080/healthz
curl --fail http://127.0.0.1:8080/readyz
```

При таком source/dev-запуске password gate выключен, если auth-переменные не объявлены. Чтобы проверить вход локально, задайте совместимые `DOCOMATOR_ACCESS_PASSWORD_HASH` и `DOCOMATOR_SESSION_SECRET` либо используйте установленный offline-профиль.

Полная проверка перед слиянием:

```bash
npm run check
```

CI дополнительно запускает Chromium user flows, real-stack smoke и сборку/повторную проверку offline archive.

## 📦 Автономная поставка

Debian и Astra Linux собираются как разные target-профили на соответствующих эталонных VM. Набор `.deb` одной ОС нельзя использовать для другой.

### 🟦 Debian

Debian bundle собирается только на согласованной Debian reference VM:

```bash
npm run bundle:offline:debian -- \
  --apt-update \
  --llama-server /srv/build/llama.cpp/llama-server \
  --model /srv/models/model.gguf
```

### 🟥 Astra Linux

Astra Linux bundle собирается отдельно на согласованной Astra Linux reference VM и требует явного Chromium-профиля этой же ОС:

```bash
npm run bundle:offline:astra -- \
  --apt-update \
  --llama-server /srv/build/llama.cpp/llama-server \
  --model /srv/models/model.gguf \
  --ux-chromium-package "$ASTRA_CHROMIUM_PACKAGE" \
  --ux-chromium-bin "$ASTRA_CHROMIUM_BIN"
```

После установки сначала задайте пароль:

```bash
sudo bash /opt/docomator/current/app/scripts/offline/set-password.sh
```

Затем используйте `first-run.sh --check`.

### Целевая приёмка

Пароль для acceptance не передаётся в командной строке и не сохраняется в bundle/актах. Создайте временный локальный файл текущего пользователя:

```bash
install -m 0600 /dev/null "$HOME/.docomator-acceptance-password"
printf '%s\n' 'ВАШ_ОБЩИЙ_ПАРОЛЬ' > "$HOME/.docomator-acceptance-password"
```

Запуск:

```bash
install -d -m 0700 "$HOME/docomator-target-acts"
"$BUNDLE_ROOT/target-acceptance.sh" \
  --config /etc/docomator/docomator.env \
  --base-url http://127.0.0.1:8080/ \
  --password-file "$HOME/.docomator-acceptance-password" \
  --output "$HOME/docomator-target-acts/debian-01"
```

Для строгого Astra-контура добавьте `--require-network --require-smtp`.

Отдельный UX-gate использует тот же безопасный password file:

```bash
"$BUNDLE_ROOT/ux-acceptance-gate.sh" \
  --base-url http://127.0.0.1:8080/ \
  --password-file "$HOME/.docomator-acceptance-password" \
  --output "$HOME/docomator-p5/automation-01"
```

После приёмки удалите временный файл:

```bash
rm -f "$HOME/.docomator-acceptance-password"
```

`target-acceptance.json`, UX metadata и release evidence содержат только признак использования пароля, а не пароль или путь к нему.

## 🔒 Эксплуатационная граница

Общий пароль — не IAM. Доступ к сети Docomator всё равно должен ограничиваться firewall/reverse proxy; при удалённом браузерном доступе используйте HTTPS. Конфигурация `/etc/docomator/docomator.env`, БД, object store и backups должны иметь минимальные системные права.

См. [SECURITY.md](SECURITY.md), [ADR-0009](docs/adr/0009-shared-password-gate.md) и [архитектуру](docs/ARCHITECTURE.md).

## ✅ Что ещё не доказано

До stable acceptance остаются внешние свидетельства:

1. чистая offline-установка/перезагрузка на Debian;
2. отдельный нативный прогон Astra Linux 1.7;
3. настоящий LibreOffice без `SKIPPED`;
4. не менее 20 DOCX + 20 XLSX, открытых также в Microsoft Office;
5. импорт/выпуск 10/100/1000;
6. restart/failure scenarios;
7. backup/restore на отдельной чистой машине;
8. два новых пользователя без устной инструкции;
9. финальный release-evidence без открытых блокеров.
