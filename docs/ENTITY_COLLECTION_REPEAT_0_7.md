# Повторяемые таблицы сотрудников — 0.7

Версия `0.7.0` добавляет упорядоченные наборы строк, принадлежащие конкретному сотруднику, и использование такого набора как источника повторяемой строки DOCX.

## Пользовательский сценарий

Например, у студента есть таблица «Пункты плана»:

| № | Наименование вопроса | Срок выполнения | Отчётность |
|---:|---|---|---|
| 1 | Обзор литературы | 15.10.2026 | Доклад |
| 2 | Эксперимент | 01.12.2026 | Отчёт |

Номер строки вычисляется по порядку и не хранится как пользовательское значение. У разных студентов может быть разное число строк.

## Данные

Определение таблицы, набор колонок, строки и значения принадлежат одному `spaceId`. Поддерживаются типы `string`, `text`, `number`, `integer`, `boolean`, `date`, `date-time`, `enum`. Сохранение всего набора строк атомарно: ошибка в одной строке не оставляет частично обновлённую таблицу.

SQL-триггеры запрещают:

- связывать владельца и таблицу из разных пространств;
- подставлять в строку поле другой схемы;
- переносить сущность в другое пространство, пока у неё существуют строки коллекции.

## Карточка сотрудника

Раздел «Таблицы и списки данных» позволяет:

- создать таблицу с понятными названиями колонок;
- добавлять, дублировать, удалять и переставлять строки;
- вставлять данные из Excel/LibreOffice;
- импортировать CSV/XLSX через preview и сопоставление колонок;
- экспортировать текущую таблицу в CSV/XLSX.

CSV-экспорт нейтрализует значения, похожие на формулы. XLSX формируется безопасным детерминированным экспортером.

## Шаблон DOCX

В строке обычной таблицы Word пользователь выбирает действие «Повторять всю строку автоматически», затем источник «Таблица из карточки каждого сотрудника» и конкретную таблицу данных. Ячейки можно связать с полями коллекции и виртуальным полем «Автонумерация 1, 2, 3…».

Обычные поля сотрудника вне повторяемой строки продолжают работать в том же документе. Это mixed-шаблон: скалярные поля владельца + одна повторяемая строка его коллекции.

Активный шаблон фиксирует точную версию схемы коллекции. Если схема изменилась, старый шаблон не начинает молча использовать новую схему — требуется перепроверка и новая активация.

## Формирование

Для режима «отдельный документ для каждого участника» worker:

1. берёт данные текущего участника;
2. заполняет обычные поля;
3. читает его коллекцию;
4. клонирует точную строку DOCX по числу записей;
5. вычисляет номер по `start + position × step`;
6. повторно считывает значения из сформированного OOXML.

Пустая обязательная коллекция даёт явную ошибку и не оставляет фиктивную образцовую строку.

## Ограничения версии 0.7

- entity-collection repeat поддержан для DOCX;
- одна такая repeat-зона на шаблон;
- один уровень вложенности, без рекурсивных repeat;
- режим выпуска — `one_per_member`;
- существующий `audience.members` repeat DOCX/XLSX сохранён без изменения;
- повторяемая entity-collection зона непосредственно в XLSX-шаблоне пока не заявляется как поддерживаемая.

## Проверка

Real-stack acceptance создаёт двух студентов, сохраняет им 3 и 5 строк соответственно, активирует DOCX-шаблон, выпускает документы по именованной группе и повторно разбирает результаты. Дополнительно проверяются cross-space denial, изменение порядка следующего выпуска без изменения уже созданного результата и явная ошибка для пустой коллекции.
