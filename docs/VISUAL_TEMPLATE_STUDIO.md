# Визуальная разметка шаблонов

Статус: **DOCX visual binding v1 реализован; XLSX использует прежний проверенный выбор ячеек**  
Версия продукта: **0.5.1 candidate / pilot**

## Назначение

Второй шаг мастера шаблона больше не обязан представлять DOCX как технический список абзацев. Для DOCX Оформлятор строит безопасную интерактивную проекцию документа: основной текст, верхние и нижние колонтитулы, сноски, обычные таблицы и текстовые фрагменты с признаком жирного/курсива отображаются в документоподобной поверхности. Пользователь нажимает нужное место или выделяет заменяемый текст непосредственно в этой проекции и затем назначает понятное поле карточки.

Визуальная поверхность **не является редактором DOCX и не становится источником истины**. Она не преобразуется обратно в Office Open XML.

```text
неизменяемый DOCX
      ↓
безопасный Document IR
      ↓
экранированная визуальная проекция
      ↓
выбор elementId / UTF-16 диапазона
      ↓
существующая серверная проверка координаты
      ↓
Template Compiler → w:sdt
      ↓
пробное заполнение → reverse-read → preview
```

## Инварианты безопасности

- Браузер не получает и не исполняет HTML из документа.
- Текст из Document IR экранируется перед вставкой в DOM.
- DOM-координаты, CSS-селекторы и положение на экране не сохраняются как привязка.
- Привязкой остаётся устойчивый `elementId`; для части абзаца дополнительно сохраняются UTF-16 `startOffset`, `endOffset` и исходный выбранный текст.
- Backend повторно разрешает `elementId` по сохранённой структуре и проверяет SHA-256 исходника/структуры перед компиляцией.
- Production renderer, `w:sdt`, repeat-row и XLSX defined names не изменены этой функцией.
- Пространство остаётся обязательной границей исходника, черновика, структуры и полей.
- Локальная модель не участвует в отображении и не получает право изменять OOXML.

## Пользовательский поток DOCX

1. Проверить и явно сохранить исходный DOCX.
2. На шаге «Поля» открыть построенную сервером структуру.
3. Увидеть документоподобную поверхность вместо основного технического списка.
4. Нажать пустой абзац, целый абзац либо ячейку таблицы — откроется прежний инспектор назначения поля.
5. Для непустого абзаца можно выделить мышью конкретный текст прямо на странице. Оформлятор пересчитает DOM-выделение в диапазон исходной строки и покажет его в существующем поле точной проверки.
6. Выбрать поле карточки, формат представления, обязательность и при необходимости repeat-row.
7. Пройти существующее пробное заполнение и обратное чтение.
8. Для точного контроля переносов страниц и сложных Office-конструкций использовать PDF-предпросмотр LibreOffice.

Для клавиатуры и нестандартной верстки под визуальной страницей остаётся раскрываемый «Список мест документа». Он вызывает тот же инспектор и не создаёт второй тип привязки.

## Что отображается в v1

- `word/document.xml` как основной текст;
- `word/headerN.xml` как верхние колонтитулы;
- `word/footerN.xml` как нижние колонтитулы;
- `word/footnotes.xml` и `word/endnotes.xml` как отдельные области примечаний;
- абзацы в исходном структурном порядке;
- обычные таблицы по `tableIndex / rowIndex / columnIndex`;
- пустые абзацы как доступные места для вставки;
- текстовые run с уже имеющимися в IR признаками `bold` и `italic`.

Если в DOCX несколько header/footer parts, они показываются отдельными подписанными областями. Текущий IR ещё не заявляет браузерную точность соответствия каждого part конкретной физической странице, поэтому UI не выдаёт приближённую раскладку за точный Word layout.

## Чего v1 не обещает

Документоподобная поверхность не заявляет пиксельную идентичность Microsoft Word/LibreOffice. В первой версии она не воспроизводит как редактируемые визуальные узлы:

- изображения и DrawingML;
- SmartArt;
- диаграммы;
- OLE/ActiveX;
- MathType как заменяемый объект;
- точную пагинацию, обтекание и плавающие рамки;
- сложную геометрию объединённых ячеек, которой нет в текущем Document IR.

Такие части исходного пакета не изменяются визуальным редактором. Их сохранность по-прежнему контролируется safe-patch renderer и отдельными Office fixtures. Пользователь получает явное пояснение, что точные переносы, рисунки и сложные Office-объекты проверяются в пробной копии/PDF.

XLSX в `0.5.1` намеренно остаётся на существующем cell-view. Это не регрессия и не скрытая имитация готовности: отдельная визуальная сетка Calc/Excel требует расширения IR размерами строк/столбцов, объединениями и стилями и должна поставляться отдельным вертикальным изменением.

## Доступность и узкие экраны

- Каждый выбираемый абзац имеет фокус и активируется `Enter`/`Space`.
- Минимальная интерактивная высота — 44 CSS px.
- Инспектор закрепляется справа только на широком экране; ниже 980 px располагается после документа.
- Таблица имеет внутреннюю прокрутку, а не расширяет весь экран.
- На ширине 320 px документ и инспектор остаются внутри viewport.
- Выбор не передаётся только цветом: элемент имеет focus/pressed-состояние, а инспектор содержит текстовое описание.
- `prefers-reduced-motion` не добавляет обязательную анимацию.

## Regression coverage

Browser regression проверяет:

1. DOCX получает визуальную страницу и область основного текста.
2. Прямое выделение `______` внутри `ФИО: ______` превращается в точный диапазон `5..11` и уходит в прежний field API вместе с `elementId`.
3. Табличный fixture отображается таблицей с двумя строками и восемью ячейками.
4. На 320 px отсутствует глобальный горизонтальный overflow, а цель выбора имеет высоту не менее 44 px.
5. Клавиатурный `Enter` открывает тот же инспектор.
6. XLSX продолжает использовать прежний проверенный выбор ячеек.

Следующее расширение должно получить собственные fixtures и regression tests до заявления поддержки: сначала безопасное отображение изображений/отношений без внешних загрузок, затем — только при отдельном renderer contract — замена изображения типизированным полем.
