# Произвольные объекты и гибкий импорт

## Назначение

Пространство Docomator — это граница данных и процессов, а не список сотрудников. Внутри одного пространства могут храниться объекты разных типов: люди, аудитории, научные статьи, оборудование, организации, договоры и иные записи. Тип задаёт смысл объекта и перечень допустимых параметров; сам объект принадлежит ровно одному пространству.

Примеры:

| Тип объекта | Отображаемое название | Возможные параметры |
|---|---|---|
| Аудитория | Аудитория 101 | корпус, этаж, номер, вместимость, площадь, оборудование |
| Научная статья | Прогноз конвективных явлений… | DOI, авторы, журнал, год, статус, ключевые слова |
| Оборудование | Лабораторная станция М-12 | инвентарный номер, модель, состояние, дата поверки |
| Человек | Иванов Иван Иванович | должность, подразделение, телефон, роль в документе |

## Инварианты модели

1. `entity_type` определяет тип объекта. Технический ключ создаётся системой и не вводится оператором.
2. `property_definition` описывает параметр: название, тип значения, единицу измерения, правила проверки и список типов объектов, к которым он применим.
3. `entity` хранит отображаемое название и статус объекта.
4. `space_entity_ownership` закрепляет объект за пространством.
5. `entity_property_values` хранит проверяемую историю значений параметров.
6. Одна сохранённая группа и один выпуск документов содержат объекты только одного типа. Это исключает подстановку параметров статьи в шаблон аудитории или параметров студента в шаблон преподавателя.
7. Поля с одинаковым названием у разных типов являются разными определениями. Например, «Номер» аудитории и «Номер» статьи не объединяются.

## Рабочий процесс

### Создание типа и параметров

1. Откройте раздел **Объекты**.
2. Создайте тип, например **Аудитория**.
3. Добавьте параметры этого типа: **Номер**, **Вместимость**, **Корпус**, **Оборудование**.
4. Добавьте записи вручную или импортируйте CSV/XLSX.

Параметры произвольных объектов по умолчанию имеют класс **Внутренние**. Для людей можно выбрать класс **Персональные**. Файлы и изображения пока не создаются через массовый табличный импорт; их следует связывать отдельным специализированным процессом.

### Использование в шаблоне

В редакторе шаблона сначала выбирается тип объектов, который заполняет документ. После этого система показывает только:

- отображаемое название объекта;
- общие поля без ограничения типа;
- параметры выбранного типа.

Для повторяемой строки каждая колонка связывается с системным номером строки, названием объекта или параметром выбранного типа. При сводном выпуске строка повторяется по одному разу на каждый объект группы.

### Формирование документов

Перед выпуском выбирается тип объектов и источник состава:

- все активные объекты выбранного типа в пространстве;
- однородная сохранённая группа;
- отмеченные вручную объекты одного типа.

Снимок состава неизменяем: последующее редактирование группы не меняет уже зафиксированный выпуск.

## Гибкий CSV/XLSX-импорт

Импорт поддерживает CSV в UTF-8 и первый лист XLSX. Ограничения текущего контура: до 8 МБ, до 100 колонок и до 1000 строк за один запуск.

Оператор явно задаёт:

1. тип создаваемых объектов;
2. колонку отображаемого названия;
3. колонку устойчивого идентификатора;
4. сопоставление остальных колонок с существующими параметрами или создание новых параметров;
5. при необходимости — создание группы из импортированных объектов.

Устойчивый идентификатор необходим для повторного импорта. Например:

- аудитория: код `ROOM-101`;
- статья: DOI или внутренний шифр;
- оборудование: инвентарный номер;
- человек: табельный номер.

Повторный импорт обновляет найденный объект. Пустая ячейка не удаляет ранее сохранённое значение. Перед записью выполняется планирование без изменения базы: оператор видит число новых, обновляемых, неизменившихся и ошибочных строк.

## Правила сопоставления

- Существующее поле ищется только среди параметров выбранного типа.
- Совпадение названия параметра другого типа не считается совпадением.
- Новое поле получает `appliesTo` выбранного типа.
- Для не-персональных типов класс данных по умолчанию — `internal`.
- Некорректное число, дата, логическое значение или вариант закрытого списка блокирует соответствующую строку.
- Смешанная группа отклоняется сервером независимо от состояния интерфейса.

## Примеры файлов

В `examples/data/` находятся безопасные вымышленные наборы:

- `employees.csv` — люди;
- `auditoriums.csv` — аудитории;
- `scientific-articles.csv` — научные статьи.

Файлы входят в проверяемый `examples/manifest.sha256` и в полный автономный комплект.

## Проверка автономной поставки

Штатная проверка проекта собирает универсальный автономный архив без внешних служб, сверяет его SHA-256, безопасно распаковывает во временный каталог и повторно запускает внутренний `verify-bundle.sh`. Так проверяется, что приложение, интерфейс произвольных объектов, миграции, производственные зависимости, примеры и документация действительно входят в поставку.

Целевые комплекты Debian и 🟥 Astra Linux дополнительно требуют набора `.deb`, собранного на эталонной машине того же выпуска и архитектуры. Поддержка конкретной платформы подтверждается только успешным `target-acceptance.sh` на целевом сервере; универсальная проверка архива не заменяет такой акт.
