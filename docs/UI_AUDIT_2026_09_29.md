## План исправлений и проверки

| Приоритет | Контур | Дефект или риск | Критерий проверки |
|---|---|---|---|
| P0 | Пространства | Поздние employee/template/workspace ответы могут заменить текущие данные. | Задержать A, открыть B, завершить A: ни данные, ни ошибки A не появляются в B. |

## Порядок

1. Воспроизвести найденные гонки и проверить полный существующий Chromium suite.
2. Внести минимальные исправления с поведенческими регрессиями; не ослаблять защиту пространств, CSP и код доступа.
3. Проверить 320/768/1440, 200%, клавиатуру, темы, сохранность ввода и отсутствие внешних запросов.
4. Запустить `npm run check`, `npm run check:release`, реальные CSV/XLSX/DOCX сценарии и offline smoke.
5. Опубликовать обычный PR, проверить exact head и обязательный CI, выполнить squash merge и проверить post-merge CI.
6. Собирать кандидат только из подтверждённого SHA. Публикацию Release и загрузку архива подтверждать GitHub API, а не локальной сборкой.
