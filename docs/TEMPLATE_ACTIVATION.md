# Сохранение шаблона и необязательный PDF-предпросмотр

Статус: **прямое сохранение проверенной версии, необязательный PDF, повторяемые строки DOCX/XLSX и единый каталог реализованы**  
Последнее обновление: **2026-07-26**

## Назначение

Подсистема завершает подготовку шаблона после пробного заполнения. Основной путь не требует преобразования в PDF:

```text
одно- или многополевая проверенная версия
        ↓
неизменяемый кандидат на выпуск
        ↓
Сохранить шаблон
        ↓
неизменяемый активный выпуск
        ↓
каталог выбранного пространства
```

Дополнительный путь используется только для визуального контроля:

```text
проверенная версия
        ↓
Создать PDF для визуальной проверки
        ↓
LibreOffice в отдельном временном профиле
        ↓
просмотр и явное подтверждение
        ↓
активный выпуск с сохранённым PDF
```

Компилятор, повторное чтение значений и контрольные суммы уже проверяют техническую корректность DOCX/XLSX. PDF не участвует в формировании рабочих документов и не является обязательным условием сохранения шаблона.

## Единый кандидат на выпуск

Одно- и многополевые проверенные версии регистрируются в общем слое кандидатов. Кандидат содержит:

- вид версии: `single` или `multi`;
- пространство и черновик;
- номер исходной проверенной версии;
- формат DOCX/XLSX;
- техническую и пробно заполненную копии;
- SHA-256 обеих копий;
- число и порядок полей;
- исходные и технические привязки;
- декларативные форматтеры;
- необязательный замороженный контракт повторяемой строки.

Кандидат неизменяем. Повторное сохранение того же кандидата не создаёт второй активный выпуск.

## Прямое сохранение без PDF

Маршруты:

```http
POST /api/v1/spaces/{spaceId}/template-test-versions/{versionId}/activate
POST /api/v1/spaces/{spaceId}/template-multi-test-versions/{versionId}/activate
```

Система:

1. проверяет принадлежность версии выбранному пространству;
2. фиксирует решение использовать успешно проверенную версию без PDF;
3. создаёт неизменяемый манифест;
4. обновляет текущий указатель каталога;
5. записывает аудит и идентификатор операции;
6. возвращает ссылку на активный DOCX/XLSX.

В манифесте сохраняется `previewMode: "skipped"`. Фиктивная операция преобразования не показывается в журнале. Запрос файла PDF для такой версии возвращает понятный конфликт: PDF не создавался, сам шаблон сохранён и готов к работе.

## Необязательный PDF-предпросмотр

Запросы:

```http
POST /api/v1/spaces/{spaceId}/template-test-versions/{versionId}/preview
POST /api/v1/spaces/{spaceId}/template-multi-test-versions/{versionId}/preview
```

Состояние и файл:

```http
GET /api/v1/spaces/{spaceId}/template-previews/{requestId}
GET /api/v1/spaces/{spaceId}/template-previews/{requestId}/file
```

После просмотра:

```http
POST /api/v1/spaces/{spaceId}/template-previews/{requestId}/activate
```

PDF создаётся сохраняемой фоновой операцией `template.preview`. Ожидающий или готовый запрос не создаёт второе задание. После ошибки пользователь может явно начать новую попытку.

Состояния:

| Машинное состояние | Пользовательское отображение |
|---|---|
| `pending`, задание ожидает | Задача поставлена в очередь |
| `pending`, задание выполняется | LibreOffice создаёт PDF |
| `ready` | Предварительный просмотр готов |
| `failed` | Предварительный просмотр не создан |

Ошибка PDF не повреждает пробно заполненную версию и не лишает пользователя возможности вернуться к прямому сохранению шаблона.

## Ограниченный запуск LibreOffice

Фоновый обработчик запускает LibreOffice:

- без оболочки и графического интерфейса;
- с отдельным временным профилем;
- с отдельными `HOME`, `XDG_*` и `TMPDIR`;
- с ограничением времени и размера;
- с завершением группы процессов при отмене;
- без передачи сетевых адресов из документа;
- с обязательной очисткой временного каталога.

Основные параметры:

```ini
DOCOMATOR_PREVIEW_ENABLED=true
DOCOMATOR_LIBREOFFICE_BIN=/usr/bin/libreoffice
DOCOMATOR_PREVIEW_TIMEOUT_MS=120000
DOCOMATOR_PREVIEW_MAX_BYTES=134217728
```

Если визуальная проверка не используется, отсутствие LibreOffice не должно блокировать прямое сохранение проверенного шаблона.

## Проверка PDF

До фиксации PDF система проверяет:

1. успешное завершение процесса;
2. наличие ровно одного результата;
3. обычный файл вместо символической ссылки;
4. непустой допустимый размер;
5. сигнатуру `%PDF-`;
6. SHA-256 фактических байтов.

PDF хранится отдельным неизменяемым объектом. Готовый PDF сам по себе не активирует шаблон: пользователь открывает его, подтверждает просмотр и нажимает кнопку сохранения версии.

## Активный выпуск

Активный выпуск хранит:

- пространство и черновик;
- кандидата и вид исходной версии;
- скомпилированный DOCX/XLSX;
- номер выпуска;
- неизменяемый манифест полей и повторов;
- режим предпросмотра `pdf` или `skipped`;
- PDF и его SHA-256 только для режима `pdf`;
- автора, идентификатор операции и время.

Манифест версии 4 фиксирует `compatibilityLevel` и `repeats` для DOCX и прежних XLSX. Новый XLSX с `_AI_META` получает версию 5 и дополнительную секцию `xlsxMetadata`. Исторические манифесты остаются неизменяемыми.

Отдельный текущий указатель определяет используемый выпуск. Переключение указателя не изменяет исторические версии и не нарушает воспроизводимость выполненных заданий.

## Каталог пространства

```http
GET /api/v1/spaces/{spaceId}/active-templates
GET /api/v1/spaces/{spaceId}/active-templates/{activeVersionId}
GET /api/v1/spaces/{spaceId}/active-templates/{activeVersionId}/files/compiled
GET /api/v1/spaces/{spaceId}/active-templates/{activeVersionId}/files/preview
```

Пользователь видит название, формат, номер выпуска, состав полей, время сохранения и ссылку на активный DOCX/XLSX. Ссылка на PDF показывается только при `previewMode: "pdf"`; иначе каталог явно сообщает, что PDF не создавался.

Идентификаторы из другого пространства не раскрывают объект.

## Пользовательский интерфейс

На заключительном шаге:

- основной акцент — **«Сохранить шаблон»**;
- вторичное действие — **«Создать PDF для визуальной проверки»**;
- интерфейс прямо сообщает, что PDF необязателен;
- введённые значения и выбранная версия сохраняются после ошибки;
- все ошибки содержат дальнейшее действие и идентификатор операции;
- журнал не показывает фиктивную операцию PDF при прямом сохранении.

## Отказоустойчивость

- прямое сохранение идемпотентно;
- очередь PDF и её состояние переживают перезапуск API и браузера;
- потерянная аренда задания не приводит к потере готового PDF;
- повтор обработчика не создаёт второй объект;
- ошибка LibreOffice отделена от проверенной версии;
- исторический выпуск не перезаписывается;
- один текущий указатель не допускает одновременно двух текущих выпусков одного черновика;
- прежние активные версии и PDF остаются доступными.

## Автоматические проверки

Испытания подтверждают:

- прямое сохранение одно- и многополевой версии без PDF;
- `previewMode: "skipped"` в активном манифесте;
- отсутствие фиктивного PDF-задания в журнале операций;
- отказ скачивания отсутствующего PDF с понятным сообщением;
- сохранение обычного пути PDF и явного подтверждения;
- полноту и порядок полей многополевого манифеста;
- manifest v5 и `_AI_META` для новых XLSX при совместимости с прежними версиями;
- перенос форматтеров и repeat-контрактов;
- изоляцию пространств;
- идемпотентное повторное сохранение;
- корректное восстановление после перезагрузки страницы.
