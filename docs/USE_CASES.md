# Каталог пользовательских кейсов Docomator

Документ отвечает на вопрос: **какой поток выбрать для конкретной рабочей задачи**.

## 1. Матрица выбора

| Задача | Данные | Шаблон | Состав | Режим результата |
|---|---|---|---|---|
| Справка каждому сотруднику | Карточки сотрудников | DOCX | группа или выбранные люди | по документу на каждого |
| Приказ на каждого студента | Студенты и реквизиты приказа | DOCX | учебная группа | по документу на каждого |
| Ведомость студентов и тем | ФИО, тема, руководитель | DOCX с повторяемой строкой | группа студентов | один сводный документ |
| Реестр сотрудников | ФИО, должность, подразделение | DOCX/XLSX со строкой списка | отдел | один сводный документ |
| Персональные договоры | Паспортные и договорные поля | DOCX | выбранные люди | по документу на каждого |
| Ежемесячная ведомость | Постоянные карточки и группа | XLSX/DOCX | сохранённая группа | расписание, сводный документ |
| Комплект документов каждому | Карточки и несколько шаблонов | комплект шаблонов | группа | по комплекту на каждого |
| Разовая выборка | Уже существующие карточки | любой активный шаблон | отмеченные вручную | выбранный режим |

## 2. Кейс: справки для сотрудников

### Исходные данные

- ФИО;
- должность;
- подразделение;
- дата приёма;
- номер справки при необходимости.

### Поток

1. Импортировать сотрудников либо заполнить карточки вручную.
2. Подготовить DOCX с образцовыми значениями.
3. Связать ФИО, должность и подразделение.
4. Выполнить пробное заполнение.
5. Активировать шаблон.
6. Выбрать группу сотрудников.
7. Выбрать **«По документу на каждого»**.
8. Исправить пропущенные значения.
9. Запустить выпуск и скачать архив.

### Ожидаемый результат

Отдельный DOCX для каждого сотрудника. Ошибка одной карточки приводит к частичному результату, а не к потере остальных файлов.

## 3. Кейс: импорт сотрудников с паспортными данными

### Рекомендуемые колонки

```text
ФИО
Табельный номер
Должность
Подразделение
Дата рождения
Серия паспорта
Номер паспорта
Кем выдан
Дата выдачи
Код подразделения
Адрес регистрации
СНИЛС
ИНН
```

### Поток

1. Сформировать XLSX, где первая строка содержит уникальные заголовки.
2. Для номеров документов использовать текстовый формат или цифровую маску с нулями.
3. Открыть массовый импорт.
4. Выбрать табельный номер как ключ.
5. Проверить, что паспортные реквизиты получили класс **«Особо чувствительные данные»**.
6. Даты назначить типом **«Дата»**.
7. Номера, серии, СНИЛС, ИНН и код подразделения оставить текстом.
8. Выполнить предварительную проверку.
9. Исправить строки с дубликатами и неверными значениями.
10. Подтвердить импорт.

### Контроль

- повторный импорт не создаёт дубликаты;
- ведущие нули сохранены;
- даты отображаются как календарные значения;
- пустые ячейки не очищают прежние реквизиты;
- данные находятся в правильном разделе.

## 4. Кейс: студенты, темы научных работ и руководители

### Рекомендуемые поля

- ФИО;
- номер зачётной книжки;
- учебная группа;
- курс;
- кафедра;
- тема научной работы;
- научный руководитель;
- должность руководителя при необходимости.

### Поток импорта

1. Скопировать таблицу из Excel либо загрузить XLSX.
2. Выбрать номер зачётной книжки как ключ.
3. Назначить учебную группу типом **«Список вариантов»**.
4. Назначить тему типом **«Длинный текст»**.
5. Назначить руководителя текстовым полем.
6. Создать группу **«Студенты — темы научных работ»**.
7. Проверить и импортировать.

### Поток Word

1. В DOCX создать заголовок таблицы и одну пустую образцовую строку.
2. Выбрать ячейку образцовой строки.
3. Запустить мастер всей строки.
4. Связать ФИО с системным именем участника.
5. Связать тему и руководителя с карточками.
6. Протестировать и активировать.
7. Выбрать группу студентов.
8. Сформировать один сводный документ.

### Ожидаемый результат

Для каждого студента создаётся отдельная строка с его темой и руководителем. Оформление образцовой строки сохраняется.

## 5. Кейс: реестр сотрудников по подразделению

### Поток

1. Импортировать сотрудников с полями `Должность` и `Подразделение`.
2. Создать группу нужного отдела либо выбрать всех активных.
3. В DOCX или XLSX подготовить строку списка.
4. Связать ФИО, должность и подразделение.
5. Активировать шаблон.
6. Создать один сводный документ.

### Варианты

- отдельная группа для каждого отдела;
- одна группа комиссии из сотрудников разных должностей;
- ежемесячный выпуск по расписанию;
- XLSX-реестр для последующей обработки.

## 6. Кейс: персональные договоры

### Особенности

Договор может использовать паспортные данные, адрес, банковские реквизиты, сумму и даты.

### Поток

1. Создать общие определения полей.
2. Импортировать или заполнить карточки.
3. Классифицировать паспортные и банковские сведения как ограниченные.
4. Подготовить DOCX и связывать только конкретные места, не заменяя подписи целиком.
5. Выполнить пробное заполнение на вымышленных данных.
6. Активировать шаблон.
7. Выбрать людей и режим **«По документу на каждого»**.
8. Проверить каждый готовый договор перед передачей.

### Ограничение

Docomator формирует документы, но не подтверждает их юридическую корректность и не заменяет обязательную проверку ответственным лицом.

## 7. Кейс: одна таблица и отдельные документы из одних данных

Одни карточки можно использовать в разных шаблонах.

### Пример

- шаблон 1: сводная ведомость всей группы;
- шаблон 2: индивидуальное уведомление каждому;
- шаблон 3: XLSX-реестр.

### Поток

1. Один раз импортировать и проверить карточки.
2. Создать три независимых активных шаблона.
3. Для каждого выпуска использовать одну и ту же группу.
4. Выбрать соответствующий режим результата.

Изменение поля в карточке применяется к будущим выпускам всех шаблонов. Уже готовые файлы не переписываются.

## 8. Кейс: повторное обновление из кадрового XLSX

### Поток

1. Сохранить прежние названия колонок или использовать псевдонимы.
2. Не менять выбранный ключ.
3. Загрузить новую выгрузку.
4. Проверить число новых и обновляемых людей.
5. Убедиться, что неожиданно новых записей нет.
6. Подтвердить импорт.

### Если появилось много новых людей

- проверьте, не изменился ли формат табельного номера;
- проверьте ведущие нули;
- убедитесь, что выбрана прежняя колонка ключа;
- не используйте изменённое ФИО как ключ;
- сравните примеры значений до подтверждения.

## 9. Кейс: закрытый справочник должностей

### Поток

1. Создать поле `Должность` типа **«Список вариантов»**.
2. Заполнить разрешённые должности.
3. Отключить принятие новых значений.
4. Импортировать таблицу.
5. Строки с опечаткой или неизвестной должностью будут отклонены.
6. Исправить исходный файл либо вручную расширить перечень.
7. Повторить проверку.

Подходит для нормативных классификаторов. Для живого справочника подразделений обычно удобнее расширяемый режим.

## 10. Кейс: исправление данных прямо перед выпуском

### Ситуация

Шаблон требует обязательное поле, но у нескольких людей оно не заполнено.

### Поток

1. Выполнить предварительную проверку.
2. Открыть блок быстрого исправления.
3. Заполнить значения у конкретных людей.
4. Сохранить.
5. Система повторит проверку.
6. После устранения пропусков запустить выпуск.

Значения сохраняются в карточках, поэтому их не потребуется вводить в следующем документе.

## 11. Кейс: частичный результат

### Ситуация

При режиме «По документу на каждого» несколько карточек некорректны или возникла ошибка формирования.

### Поток

1. Скачать уже готовые документы.
2. В результатах открыть ошибочные единицы.
3. Исправить данные или шаблон.
4. Нажать повтор только неуспешных строк.
5. Проверить итоговый комплект.

Не запускайте весь состав заново без необходимости: это создаст новые версии документов для уже успешных людей.

## 12. Кейс: ежедневный или ежемесячный реестр

### Поток

1. Подготовить постоянную группу.
2. Активировать сводный шаблон.
3. Создать расписание.
4. Выбрать группу и режим **«Один сводный документ»**.
5. Указать часовой пояс и время.
6. Настроить сетевую папку или электронную почту.
7. Включить правило.
8. После первого запуска проверить результат и доставку.

### Контроль

- шаблон остаётся активным;
- группа содержит актуальных людей;
- у всех заполнены обязательные поля;
- worker работает;
- канал доставки доступен;
- свободного места достаточно.

## 13. Кейс: разовая комиссия

1. Откройте список участников раздела.
2. Отметьте нужных людей.
3. Не создавайте постоянную группу, если состав больше не понадобится.
4. Создайте снимок аудитории из отмеченных.
5. Выберите шаблон и режим.
6. Запустите выпуск.

Снимок сохранит выбранный состав даже после снятия флажков в браузере.

## 14. Кейс: новая версия шаблона

### Ситуация

В документе изменилась формулировка или расположение полей.

### Поток

1. Не изменять активированную версию.
2. Загрузить новый исходный DOCX/XLSX.
3. Построить новую структуру.
4. Связать поля заново.
5. Выполнить пробное заполнение.
6. Сравнить готовую копию с прежней.
7. Активировать новую версию.
8. Проверить первый выпуск.

История документов продолжает ссылаться на фактически использованную версию.

## 15. Кейс: недоступен локальный ИИ

Активированные шаблоны должны продолжать работать детерминированно.

1. Используйте ручное сопоставление полей.
2. Заполните данные через формы и импорт.
3. Выпускайте документы по активным шаблонам.
4. Диагностику модели выполняйте отдельно.

Недоступность локальной модели не должна блокировать уже настроенный производственный процесс.

## 16. Кейс: ошибка сетевой доставки

1. Не повторяйте формирование документа, если файл уже готов.
2. Проверьте результат в локальном хранилище.
3. Проверьте монтирование сетевой папки и контрольный файл.
4. Устраните проблему доступа.
5. Повторите только доставку.

Ошибка доставки не должна удалять готовый файл.

## 17. Кейс: восстановление после обновления

1. До обновления создать резервную копию.
2. Выполнить обновление и миграцию.
3. Проверить `/readyz`.
4. Проверить API, worker и хранилище.
5. Открыть веб-интерфейс.
6. Проверить карточки, шаблоны, расписания и результаты.
7. Сформировать контрольный документ.
8. При неуспехе использовать штатный откат или восстановление.

## 18. Кейс: диагностика жалобы пользователя

Запишите:

- время;
- действие;
- раздел;
- шаблон;
- ФИО или группу без копирования ограниченных значений в открытый канал;
- состояние;
- идентификатор операции;
- полный текст сообщения;
- воспроизводится ли ошибка повторно.

После этого проверьте журнал API, журнал worker, состояние очереди, доступность файлов и свободное место.

## 19. Что не следует делать

- не хранить группу студентов одним текстом в карточке;
- не использовать ФИО как постоянный ключ при наличии номера;
- не создавать отдельное поле `Должность Иванова` для каждого человека;
- не заменять весь абзац, если должна сохраниться подпись;
- не активировать шаблон без пробной проверки;
- не запускать сводный документ с пропущенными обязательными полями;
- не публиковать Docomator напрямую в Интернет;
- не считать класс чувствительности пользовательским разграничением доступа;
- не редактировать применённые миграции и активированные версии;
- не использовать макросы, ActiveX и исполняемые вложения в шаблонах.
