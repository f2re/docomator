# Код доступа: первый запуск, смена и восстановление

Оформлятор работает в модели общего доверенного рабочего пространства. Код доступа — четыре цифры, одинаковые для всех допущенных рабочих мест. Это не логин, не учётная запись пользователя и не замена firewall/reverse proxy/HTTPS.

## Первый запуск

Откройте Оформлятор в браузере. Экран «Код доступа» предложит задать ровно четыре цифры. Имя пользователя и повторный ввод не требуются. После сохранения рабочая область откроется автоматически.

Код не хранится открытым текстом. В конфигурации и SQLite сохраняется только scrypt-хэш; браузерная сессия использует отдельный случайный session secret.

## Смена кода на сервере

```bash
sudo /opt/docomator/current/set-access-code.sh
```

Для автоматизированного защищённого ввода:

```bash
printf '%s\n' '0427' | sudo /opt/docomator/current/set-access-code.sh --code-stdin
```

Не передавайте код аргументом командной строки: он может попасть в историю оболочки или список процессов.

## Если код забыт

На самом экране доступа показана эта же команда восстановления:

```bash
sudo /opt/docomator/current/reset-access-code.sh
```

или:

```bash
sudo /opt/docomator/current/first-run.sh --reset-code
```

Старый код не требуется. Новый код должен состоять ровно из четырёх цифр. Recovery:

- не изменяет документы, сущности, пространства, шаблоны, задания и настройки предметной области;
- синхронизирует credential hash в конфигурации и историческом storage из миграции 0031;
- ротирует session secret, поэтому все ранее открытые браузерные сессии закрываются;
- перезапускает `docomator-api.service`, если не указан служебный `--no-restart`.

После восстановления откройте `/access` и введите новый код. Также проверьте `/healthz` и `/readyz`.

## Обновление со старой версии

Начиная с `0.6.3` канонический env-key — `DOCOMATOR_ACCESS_CODE_HASH`. Runtime может прочитать старый `DOCOMATOR_ACCESS_PASSWORD_HASH` только для безопасного перехода с предыдущей установки. При штатной смене кода канонический ключ создаётся автоматически; legacy-ключ синхронизируется только если уже существовал для возможности rollback.

Скрипты `set-password.sh` и `reset-password.sh` сохранены только как короткие compatibility wrappers для старых эксплуатационных команд. Новая документация и автоматизация не должны их использовать.

## Если браузер показывает системное окно «имя пользователя / пароль»

Встроенный Оформлятор не использует HTTP Basic Authentication и не выдаёт `WWW-Authenticate`. Нативное двухполевое окно браузера в актуальной версии означает, что авторизацию добавил внешний reverse proxy/веб-сервер или другой инфраструктурный слой. Проверьте его конфигурацию отдельно.
