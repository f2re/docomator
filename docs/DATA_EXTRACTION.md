# Извлечение данных из DOCX/XLSX

Статус: реализуемый контракт версии `0.7.0`.

## Назначение

Раздел **«Извлечение данных»** превращает проверенный DOCX/XLSX в структурированные наборы данных без обязательной предварительной ручной разметки. Базовый результат строится детерминированно по Document IR и работает без Internet и без LLM. Пользователь может визуально исправить предложенную схему и конкретные значения; исходный автоматический результат при этом не переписывается.

Текущий подтверждаемый формат — только DOCX и XLSX. PDF, ODT/ODS, сканы и OCR не считаются поддержанными до появления отдельного безопасного adapter, fixtures и acceptance.

## Связанные требования

Контур следует `SYS-001`, `SYS-004—008`, `SPACE-001`, `SPACE-005`, `DATA-006`, `DATA-009—011`, `DATA-015—024`, `TPL-001—004`, `TPL-013—023`, `AI-001—010` и общим UX/security требованиям. Он не ослабляет ADR-0008 и ADR-0011.

## Pipeline

```text
DOCX/XLSX
→ existing secure intake
→ bounded Document IR
→ deterministic proposal
→ visual correction
→ immutable extraction template/recipe
→ batch extraction
→ structured issues + provenance
→ separate operator corrections
→ CSV / следующий typed-import bridge
```

### 1. Безопасный анализ

Документ проходит тот же Office intake, что и шаблоны: лимиты ZIP/XML, проверку путей, relationships, macros/ActiveX/OLE и вычисление SHA-256. Браузер не исполняет содержимое документа и не становится источником координат.

### 2. Автоматическое предложение

Без LLM система ищет только проверяемые структурные закономерности:

- таблицу с выраженной строкой заголовков и первой строкой данных;
- повторяемые строки таблицы;
- двухколоночные блоки «поле — значение»;
- безопасно выводимые типы `text`, `integer`, `number`, `date`.

Предложение содержит реальные `elementId` только как внутренние координаты, `confidence` и объяснимую причину. Усечённая структура не превращается в автоматический шаблон.

### 3. Визуальная коррекция

UI сначала показывает найденный результат. Оператор может добавить/убрать место, переименовать колонку, изменить тип и переключить scalar/repeat. Технические IDs/OOXML обычному пользователю не показываются. Ошибка сервера не очищает выбранный файл, разметку или введённые исправления.

### 4. Сохранённый шаблон извлечения

После явного подтверждения исходник повторно валидируется и сохраняется immutable by SHA-256. Шаблон хранит структурные селекторы, независимые от SHA конкретного образца, поэтому применяется к однотипным следующим документам. В первой версии разрешены scalar fields и одна повторяемая таблица.

### 5. Batch run

Один запуск принимает до 100 проверенных источников. Для каждого документа сохраняются имя, SHA-256, автоматический результат, structured issues и отдельные corrections. Idempotency key не позволяет создать второй логически тот же запуск. Состояние восстанавливается после restart API.

### 6. Ошибки и provenance

Проблема содержит стабильный `code`, severity, поле/строку, структурную координату и исходное значение, если они известны, а UI формирует поверх этого понятные `message` и `suggestedAction`. Значение не считается найденным, если selector отсутствует или тип не подтверждён.

### 7. Экспорт и запись в предметные данные

`0.7.0` экспортирует подтверждённый результат в CSV с обязательным именем исходного документа и нейтрализацией spreadsheet formulas. Сам extraction preview/run не создаёт entities и property definitions.

Прямое применение к typed entity import выполняется отдельным bridge поверх существующего `headers + rows + mappings + sourceSha256` и не должно создавать второй импортёр. Повторяемые вложенные наборы должны использовать `entity collections` (#128—#132), а не отдельную storage model.

## Инварианты

- каждый persisted template/run/item/correction принадлежит одному `spaceId`;
- A не читает и не меняет extraction resources B;
- GET/preview не меняют ownership и не создают пользовательские поля;
- automatic result immutable; corrections хранятся отдельно и versioned;
- документ не влияет на policy/tools и не может породить shell/SQL/path/OOXML action;
- LLM, когда будет подключён, только ранжирует bounded candidates и не обязателен для работы;
- одинаковый recipe должен работать на разных source SHA при совпадающей структурной форме;
- неподдержанная/изменившаяся структура даёт явную проблему, а не смещение значений.

## Acceptance

Минимальный regression/acceptance набор: DOCX key/value + table, XLSX table; разные source SHA; missing/reordered cells; blank cells, Excel dates, mixed types и multiline; batch 1/10/100; partially invalid batch; corrections; restart; idempotency; два пространства с одинаковыми именами; CSV formula neutralization; браузерные 320/768/1440, 200% zoom, keyboard, light/dark и отсутствие horizontal overflow.
