# Следующие итерации

Текущая версия: `0.6.7`.

Статус: `candidate / pilot`.

`0.6.4` закрыл пользовательский разрыв доступа: первый запуск задаёт один общий 4-значный код без логина/пароля, старый `/login` только переводит на новый PIN-экран, действующая session не требует повторного ввода, а экран проверяется на 320 px и с экранной/обычной клавиатурой. `0.6.5` исправил выявленный в реальном использовании разрыв шаблонизатора: все поля сотрудников текущего пространства доступны при сопоставлении, а выбор параметра работает обычной прокруткой и клавиатурой без обязательного поиска. `0.6.6` исправляет рабочую компоновку самого сопоставления: документ и форма не конкурируют за ширину, а длинный список не выходит за границы инспектора. `0.6.7` закрывает подтверждённые UX-разрывы выпуска: единая шкала шагов, одно доминирующее действие, searchable-select для шаблона/группы и безопасный повтор после ошибки без потери подготовленного состава. Граница shared trusted workspace и ADR-0011 не меняются.

## P0 — дефекты реального сценария и внешняя приёмка

- #124: сквозная доступность пользовательских полей сотрудников текущего пространства в шаблонизаторе.
- #125: рабочая компоновка шага сопоставления и полноценная навигация длинного списка.
- #126: E2E `пространство → сотрудники/группа → шаблон → заполненный документ` и cross-space isolation.
- #67: Debian target acceptance.
- #68: Astra Linux target acceptance.
- #69: реальный Office/LibreOffice corpus, 10/100/1000, restart/retry, backup/restore, update/rollback.
- #70: P5 и финальный release evidence.
- #81: включить branch protection/ruleset для `main` и закрепить обязательные проверки.
- #33: закрывается только после завершения перечисленных доказательств для одного точного release binding.

## Ограничение объёма разработки

Новые продуктовые функции не добавляются вне дефектов, выявленных реальным target/Office/P5-потоком. Такой дефект исправляется по первопричине и получает regression coverage; сквозной сценарий #126 является частью доказательства исправления, а не отдельным расширением продукта.

Applied migrations не переписываются, граница shared trusted workspace не меняется, микросервисы/облачные зависимости/новый frontend framework не вводятся.
