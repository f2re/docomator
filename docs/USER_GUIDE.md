# Руководство оператора Docomator

Версия руководства: **1.0**  
Область: ежедневная работа оператора, подготовка данных, настройка шаблонов, выпуск и доставка документов.

> В веб-интерфейсе это руководство доступно через пункт **«Руководство»**. Встроенный центр помощи работает без Интернета.

## 1. Как устроен рабочий процесс

Docomator использует последовательность:

1. выбрать раздел данных;
2. добавить людей вручную или импортировать таблицу;
3. при необходимости собрать людей в группу;
4. загрузить DOCX/XLSX-шаблон;
5. связать изменяемые места шаблона с полями карточек;
6. выполнить пробное заполнение;
7. активировать проверенную версию шаблона;
8. выбрать получателей и режим результата;
9. проверить недостающие сведения;
10. запустить формирование;
11. скачать результат или передать его по настроенному каналу;
12. при повторяющемся процессе создать расписание.

## 2. Основные понятия

| Понятие | Что означает | Когда использовать |
|---|---|---|
| Раздел данных | Организационный набор людей, групп, шаблонов и процессов | Отдельное подразделение, факультет, филиал, проект |
| Карточка человека | ФИО, статус и значения полей конкретного человека | Для подстановки данных в документы |
| Поле | Общее определение значения: должность, тема работы, дата рождения | Когда одинаковый вид сведений нужен у разных людей |
| Группа | Сохраняемый упорядоченный состав людей | Для повторных выпусков по одному составу |
| Снимок состава | Неизменяемая фиксация выбранных людей и их порядка | Создаётся перед запуском документа |
| Шаблон | Проверенный DOCX/XLSX с привязанными полями | Основа готового документа |
| Один документ на каждого | Отдельный файл для каждого участника | Приказы, справки, заявления, договоры |
| Один сводный документ | Один файл с таблицей или списком участников | Реестры, ведомости, списки студентов |
| Расписание | Правило автоматического повторного выпуска | Ежедневные, еженедельные, ежемесячные документы |

Разделы не являются границами доступа. Все пользователи, допущенные в корпоративный контур, работают с общими данными.

## 3. Быстрый старт: первый рабочий документ

### Исходные условия

Есть два сотрудника и DOCX-справка, в которой должны появиться ФИО и должность.

### Порядок

1. Откройте **«Сотрудники»**.
2. Нажмите **«Добавить сотрудника»**.
3. Укажите ФИО.
4. Нажмите **«Добавить поле»**, создайте поле **«Должность»** и введите значение.
5. Сохраните карточку и повторите для второго сотрудника.
6. Откройте **«Шаблоны»** и загрузите DOCX.
7. Проверьте файл и сохраните безопасную копию.
8. Постройте структуру документа.
9. Выберите место ФИО и свяжите его с **«ФИО сотрудника»**.
10. Выберите место должности и свяжите его с полем **«Должность»**.
11. Выполните пробное заполнение всех полей.
12. Активируйте проверенную версию.
13. Откройте **«Создать документы»**.
14. Выберите шаблон и сотрудников.
15. Выберите режим **«По документу на каждого»**.
16. Выполните проверку данных и запустите выпуск.
17. Скачайте готовые файлы в разделе **«Результаты»**.

## 4. Разделы данных

### Когда нужен новый раздел

Создавайте отдельный раздел, когда данные относятся к разным подразделениям, филиалам, проектам или независимым наборам документов. Не создавайте новый раздел только ради временной выборки: для этого предназначена группа.

### Создание и выбор

1. Откройте **«Настройки» → «Разделы данных и группы»**.
2. Создайте раздел и задайте понятное название.
3. Выберите его как текущий.
4. Все новые люди, группы, шаблоны и запуски будут относиться к выбранному разделу.

### Важные правила

- человек принадлежит одному разделу;
- группа содержит только людей своего раздела;
- шаблон и его версии используются только внутри своего раздела;
- изменение текущего раздела во время импорта или настройки отменяет незавершённый локальный выбор и требует повторной проверки.

## 5. Карточки людей

### Добавление вручную

1. Откройте **«Сотрудники»**.
2. Нажмите **«Добавить сотрудника»**.
3. Укажите ФИО и статус.
4. Добавьте существующие поля или создайте новые.
5. При создании нового поля подтвердите, что оно станет доступно всем карточкам.
6. Сохраните карточку.

### Редактирование

Откройте сотрудника из списка, измените ФИО, статус или значения полей и сохраните. Не создавайте вторую карточку только из-за изменения должности или темы работы.

### Типы полей

| Тип | Примеры |
|---|---|
| Короткий текст | номер документа, телефон, должность |
| Длинный текст | тема научной работы, примечание, кем выдан паспорт |
| Список вариантов | подразделение, должность, учебная группа, статус |
| Число | оклад, ставка, коэффициент |
| Целое число | курс, стаж в полных годах |
| Да / нет | признак допуска, участие |
| Дата | дата рождения, дата выдачи паспорта |
| Дата и время | время события или регистрации |

### Класс данных

- **Открытые** — допустимы для публичных материалов;
- **Внутренние** — обычные рабочие сведения;
- **Персональные** — сведения о человеке;
- **Ограниченные** — паспортные данные, СНИЛС, адрес регистрации и другие особо чувствительные сведения.

Класс влияет на маскирование, журналирование и передачу локальной модели, но не является пользовательским правом доступа.

## 6. Массовый импорт людей и заполненных полей

### Поддерживаемые источники

- CSV;
- XLSX, первый рабочий лист;
- диапазон, скопированный из Excel или LibreOffice.

Первая строка содержит заголовки, каждая следующая строка — одного человека.

### Рекомендуемая таблица сотрудников

```text
ФИО	Табельный номер	Должность	Подразделение	Дата рождения	Серия паспорта	Номер паспорта	Кем выдан	Дата выдачи	Код подразделения
Иванов Иван Иванович	Т-001	Инженер	Метеослужба	1985-05-10	1234	567890	ОВМ Центрального района	2020-03-12	770-001
```

### Порядок импорта

1. Откройте **«Сотрудники»**.
2. Нажмите **«Импортировать список»**.
3. Выберите файл либо режим **«Вставить из Excel»**.
4. Укажите колонку ФИО.
5. Выберите колонку для повторного распознавания человека.
6. Проверьте сопоставление всех колонок.
7. Для новых полей проверьте название, тип и класс данных.
8. Для перечней проверьте варианты и режим пополнения.
9. При необходимости включите создание группы.
10. Нажмите **«Проверить»**.
11. Исправьте строки с ошибками или исключите ненужные колонки.
12. Подтвердите импорт.

### Как выбирать ключ повторного импорта

Предпочтительный порядок:

1. табельный номер;
2. номер зачётной книжки;
3. кадровый идентификатор;
4. рабочая электронная почта;
5. иной неизменяемый код;
6. ФИО — только при отсутствии стабильного идентификатора.

Одинаковый ключ в двух строках одного файла считается ошибкой. При повторной загрузке строка с тем же ключом обновляет существующую карточку.

### Автоматическое сопоставление

Система учитывает:

- точное название;
- псевдонимы поля;
- смысловые варианты названия;
- частичное совпадение слов;
- ранее подтверждённые решения этого браузера.

Оператор обязан проверить колонки с низкой уверенностью и новые поля.

### Пустые ячейки

Пустая ячейка не удаляет сохранённое значение. Для намеренной очистки откройте карточку человека и измените поле вручную.

### Перечни

Для должности, подразделения, группы и статуса используйте **«Список вариантов»**.

- расширяемый перечень принимает новое значение и добавляет его в варианты;
- закрытый перечень отклоняет строку с неизвестным значением.

### Даты и ведущие нули XLSX

Docomator учитывает форматы ячеек Excel. Числовая дата преобразуется в календарную дату, а идентификатор с маской `0000 000000` сохраняется как `0123 456789`. Для критичных номеров всё равно рекомендуется хранить ячейку как текст.

### Ограничения одного импорта

- до 8 МБ;
- до 1000 строк данных;
- до 100 колонок;
- первый лист XLSX;
- обычный XLSX без макросов, ActiveX, вложенных объектов и внешних связей.

## 7. Кейс: студенты и темы научных работ

Не помещайте весь состав в одно сложное поле. Каждый студент должен быть отдельной карточкой, а тема, руководитель и группа — отдельными полями.

### Таблица

```text
ФИО	Номер зачётной книжки	Учебная группа	Тема научной работы	Научный руководитель	Кафедра	Курс
Иванов Иван Иванович	ЗК-001	М-21	Оценка точности прогноза осадков	Петров Пётр Петрович	Метеорология	4
Смирнова Анна Сергеевна	ЗК-002	М-21	Обработка данных радиозондирования	Сидорова Мария Андреевна	Метеорология	4
```

### Порядок

1. Вставьте таблицу или загрузите XLSX.
2. Выберите номер зачётной книжки как ключ.
3. Свяжите ФИО с именем карточки.
4. Создайте или выберите поля темы, руководителя, группы, кафедры и курса.
5. Для учебной группы выберите расширяемый перечень.
6. Создайте группу **«Студенты — темы научных работ»**.
7. Проверьте и подтвердите импорт.
8. Настройте повторяемую строку Word.
9. Создайте один сводный документ по группе.

## 8. Группы и выбор участников

### Когда использовать группу

- один и тот же состав нужен многократно;
- документ формируется по расписанию;
- нужен понятный именованный набор: курс, отдел, комиссия, поток.

### Разовый выбор

Отметьте людей вручную и сразу создайте снимок состава. Это подходит для единичного выпуска.

### Сохранённая группа

Отметьте людей, создайте группу и задайте название. Группу можно редактировать. Уже созданные снимки состава от этого не изменяются.

### Все активные

Используйте источник **«Все активные»**, когда документ должен включать всех людей текущего раздела со статусом «Активный».

## 9. Подготовка DOCX-шаблона

### Рекомендации

- используйте обычный DOCX без макросов;
- уберите внешние ссылки и встроенные объекты;
- оставьте понятные подписи или образцовые значения;
- для таблицы создайте одну образцовую строку данных;
- не объединяйте ячейки по вертикали в повторяемой строке;
- избегайте вложенных таблиц внутри повторяемой строки.

### Полный поток

1. Откройте **«Шаблоны»**.
2. Выберите DOCX.
3. Выполните проверку безопасности.
4. Сохраните принятую копию.
5. Постройте структуру.
6. Выберите абзац, текстовый фрагмент или ячейку таблицы.
7. Свяжите место с существующим полем либо создайте новое.
8. Настройте формат ФИО, числа или даты при необходимости.
9. Повторите для всех изменяемых мест.
10. Выполните пробное заполнение всех полей.
11. Просмотрите готовую копию.
12. Активируйте проверенную версию.

### Замена части текста

Если в абзаце есть подпись `Должность: ____`, выделите только `____`. Выбор замены всего абзаца удалит подпись.

## 10. Таблица Word: одна строка на каждого человека

### Образец

| № | ФИО | Тема научной работы | Научный руководитель |
|---|---|---|---|
|  |  |  |  |

### Настройка

1. Выберите любую ячейку образцовой строки.
2. Нажмите **«Настроить строку»**.
3. Проверьте сопоставление каждой колонки.
4. Для ФИО выберите **«ФИО участника»**.
5. Для номера по порядку выберите поле позиции участника, если оно предложено, либо оставьте колонку без автоматического заполнения.
6. Свяжите тему и руководителя с соответствующими полями.
7. Отметьте обязательные значения.
8. Нажмите **«Связать всю строку»**.
9. Выполните пробное заполнение.
10. Активируйте шаблон.
11. При выпуске выберите группу и режим **«Один сводный документ»**.

Docomator копирует образцовую строку для каждого участника и сохраняет оформление исходной строки.

### Ограничения

- одна повторяемая область в шаблоне первой версии;
- до 1000 участников;
- без вложенных повторов;
- сложное вертикальное объединение и вложенные таблицы могут быть отклонены.

## 11. Подготовка XLSX-шаблона

1. Загрузите обычный XLSX.
2. Выполните проверку.
3. Постройте структуру первого листа и других доступных листов шаблона.
4. Выберите ячейки для отдельных полей.
5. Для списка выберите образцовую строку или непрерывный диапазон.
6. Не используйте формульную ячейку как изменяемое поле.
7. Выполните пробное заполнение.
8. Активируйте версию.

Формулы вне изменяемой области сохраняются. Формулы и ссылки, которые нельзя безопасно перенести при повторе, блокируют настройку.

## 12. Пробное заполнение и активация

Шаблон нельзя использовать в промышленном выпуске сразу после сопоставления.

### Пробная проверка

- для одного поля доступна одиночная проверка;
- для нескольких полей или повторяемой строки используется проверка всего набора;
- система записывает значения в копию;
- затем считывает их обратно;
- расхождение блокирует активацию.

### Перед активацией проверьте

- все поля находятся на правильных местах;
- подписи и оформление не повреждены;
- даты, числа и ФИО представлены правильно;
- таблица создаёт нужное количество строк;
- обязательные поля заданы верно.

Активация создаёт неизменяемую версию. Для изменения шаблона подготовьте новую версию.

## 13. Создание документов

### Порядок

1. Откройте **«Создать документы»**.
2. Выберите активированный шаблон.
3. Выберите источник участников:
   - все активные;
   - сохранённая группа;
   - отмеченные вручную.
4. Выберите режим:
   - один документ на каждого;
   - один сводный документ.
5. Подготовьте снимок состава.
6. Запустите предварительную проверку данных.
7. Исправьте недостающие значения.
8. Подтвердите запуск.
9. Следите за состоянием задания.
10. Перейдите к результатам.

### Один документ на каждого

Подходит для справок, заявлений, договоров, уведомлений и приказов. Ошибка одного участника не должна уничтожать готовые документы остальных; итог может быть частичным.

### Один сводный документ

Подходит для реестров, ведомостей и таблиц. Если обязательное поле отсутствует хотя бы у одного участника, запуск блокируется до исправления.

## 14. Предварительная проверка и быстрое исправление

Перед запуском система показывает:

- число участников;
- число готовых карточек;
- список отсутствующих обязательных полей;
- возможность запуска;
- будет ли результат частичным.

Недостающее значение можно заполнить прямо в форме проверки. Оно сохраняется в карточке человека и используется в последующих документах.

Если поле шаблона не связано с общей карточкой, вернитесь в **«Шаблоны»** и перепривяжите его.

## 15. Результаты и повтор неуспешных строк

### Состояния

| Состояние | Значение |
|---|---|
| Ожидает | Задание поставлено в очередь |
| Выполняется | Фоновый обработчик формирует файлы |
| Завершено | Все ожидаемые файлы готовы |
| Частично | Часть файлов готова, часть завершилась ошибкой |
| Ошибка | Готовых файлов нет или задание не может продолжиться |

### Действия

- скачать отдельный файл;
- скачать архив комплекта;
- повторить только неуспешные единицы;
- посмотреть идентификатор операции;
- проверить причину ошибки;
- выполнить доставку по разрешённому каналу.

Повтор использует тот же снимок состава и активную версию шаблона, поэтому состав не изменяется неожиданно.

## 16. Расписания

### Когда применять

- ежедневный реестр;
- еженедельная ведомость;
- ежемесячный комплект документов;
- повторный выпуск по постоянной группе.

### Создание

1. Откройте **«Расписания»**.
2. Нажмите создание правила.
3. Выберите шаблон и раздел.
4. Выберите источник участников.
5. Укажите режим результата.
6. Задайте периодичность, дату, время и часовой пояс.
7. Настройте доставку при необходимости.
8. Проверьте ближайший запуск.
9. Включите правило.

### Поведение при ошибке

Если обязательных данных не хватает, система не должна отправлять неполный документ. Исправьте карточки и повторите запуск. Отключение расписания не удаляет историю прежних запусков.

## 17. Доставка результатов

### Электронная почта

- сервер SMTP настраивает администратор;
- адреса получателей должны быть разрешены политикой организации;
- перед отправкой проверяйте состав вложений;
- пароль SMTP не показывается в журналах и интерфейсе.

### Сетевая папка

- путь должен входить в разрешённый перечень;
- сетевой ресурс должен быть смонтирован;
- Docomator проверяет контрольный файл каталога;
- запись выполняется через временный файл и атомарное переименование;
- ошибка доставки не удаляет сформированный файл из локального хранилища.

## 18. Резервное копирование и восстановление

### Перед изменениями

Создавайте резервную копию перед обновлением, миграцией, массовым импортом критичных данных и изменением инфраструктуры.

### Минимальные команды

```bash
npm run backup
npm run restore
```

Фактические параметры и пути приведены в `docs/OPERATIONS.md` и `docs/OFFLINE_DEPLOYMENT.md`.

После восстановления проверьте:

- готовность API;
- доступность базы;
- список сотрудников;
- активные шаблоны;
- результаты и расписания;
- работу фонового обработчика.

## 19. Диагностика

### Что записать при ошибке

- точное действие;
- время;
- название раздела и шаблона;
- состояние задания;
- идентификатор операции;
- сообщение интерфейса;
- сохранились ли введённые данные.

### Типовой порядок

1. Не закрывайте форму, если введённые значения ещё нужны.
2. Скопируйте идентификатор операции.
3. Нажмите **«Повторить»**, если причина могла быть временной.
4. Проверьте раздел **«Настройки» → диагностика и готовность**.
5. Проверьте процессы API и worker.
6. Проверьте свободное место и права каталога данных.
7. Для шаблонов выполните пробную проверку заново.

## 20. Частые ошибки

| Ситуация | Причина | Действие |
|---|---|---|
| Импорт создаёт дубликаты | Выбран изменяемый ключ, например ФИО | Используйте табельный номер или иной постоянный код |
| Дата из Excel выглядит числом | Ячейка не имеет корректного формата даты | Задайте формат даты или сохраните значение текстом |
| Потерян ноль в номере | Excel хранил номер как обычное число | Используйте текстовый формат либо цифровую маску |
| Строка импорта отклонена | Пустой ключ, дубликат или неверный тип | Исправьте указанную строку и повторите проверку |
| Нет нужного поля в шаблоне | Оно не создано либо относится к другому типу | Создайте поле в карточке или мастере шаблона |
| Сводный документ не запускается | У участника отсутствует обязательное значение | Заполните его в предварительной проверке |
| Повторяемая строка недоступна | Выбрана сложная строка, вложенная таблица или другой повтор | Упростите строку или используйте новый шаблон |
| Результат частичный | Ошибка только у части участников | Исправьте причины и повторите неуспешные единицы |
| Расписание не выпустило документ | Недостающие данные, выключенное правило или недоступная доставка | Проверьте правило, карточки и канал доставки |

## 21. Безопасность и эксплуатационные границы

- приложение работает без внешнего Интернета;
- в Docomator нет входа, ролей и пользовательских прав;
- доступ ограничивает корпоративная сеть и операционная система;
- не размещайте сервер в открытом Интернете;
- каталог данных должен быть доступен только системному пользователю службы и администраторам;
- паспортные и иные ограниченные сведения не следует передавать локальной модели без разрешённой политики;
- исходные и готовые документы могут содержать персональные данные;
- резервные копии защищаются так же, как рабочая база;
- не включайте макросы и исполняемые вложения в шаблоны.
