# ADR-0010: публичное stateless-форматирование DOCX по ГОСТ/ЕСКД

Статус: accepted

Дата: 2026-08-12

## Контекст

Основное приложение Оформлятор защищено одним общим паролем доверенного рабочего контура. Владельцу продукта требуется, чтобы базовая функция оформления DOCX по ГОСТ/ЕСКД была доступна пользователю без входа.

Открывать без пароля пространства, публикации, шаблоны, импорт, результаты или иные сохраняемые данные нельзя: это разрушило бы действующую границу безопасности.

## Решение

Разрешается отдельная публичная поверхность `/gost` и только три связанных API: получение списка профилей, анализ одного DOCX и формирование новой DOCX-копии.

Публичный режим:

- не принимает `spaceId` и не читает пространства;
- не использует SQLite, quarantine, object store, worker queue, публикации или пользовательские сущности;
- не сохраняет исходный документ и результат на сервере;
- обрабатывает один HTTP-файл за запрос с жёстким лимитом размера и ограничением числа одновременных операций;
- использует тот же детерминированный OOXML formatter, что и авторизованный пакетный режим;
- не вызывает LLM, LibreOffice, shell, SQL или внешнюю сеть;
- сохраняет same-origin защиту для browser mutation;
- не является нормативной экспертизой документа.

Авторизованный режим остаётся отдельным: он может сохранять исходники в пространстве, ставить пакетное задание worker, хранить историю и повторять только ошибки.

## Последствия

Password gate имеет явно перечисленный allowlist публичных путей. Regression test обязан одновременно доказать, что `/gost` и публичный formatter работают без cookie, а обычный `/api/v1/spaces` без cookie возвращает `401`.

Любое расширение публичного allowlist на сохраняемые данные, произвольные пути, внешние действия или пользовательские сущности требует отдельного ADR и повторного security review.
