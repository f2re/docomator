# ADR-0009: Общий пароль входа в доверенном контуре

Статус: принято

Дата: 2026-08-08

## Контекст

ADR-0006 закрепил эксплуатацию Оформлятор без встроенной аутентификации: безопасность обеспечивалась внешним доверенным сетевым и системным периметром. Для фактической эксплуатации этого недостаточно: открытие веб-интерфейса по адресу приложения не должно немедленно давать доступ к рабочим данным.

При этом проекту по-прежнему не нужны пользователи, роли, персональные кабинеты и разграничение прав внутри приложения. Пространства остаются организационными границами данных, а не ACL.

## Решение

Оформлятор получает один общий пароль приложения.

- Все интерактивные UI-страницы и предметные API требуют успешного входа.
- `/healthz` и `/readyz` остаются без входа для systemd, reverse proxy и target acceptance.
- В приложении нет пользователей, ролей, профилей и отдельных прав. После входа клиент имеет тот же общий доступ к данным, что и раньше внутри доверенного контура.
- Пароль не хранится в открытом виде. Конфигурация содержит только scrypt-хэш с солью и параметрами.
- Успешный вход создаёт подписанную сервером `HttpOnly`, `SameSite=Strict` cookie с ограниченным сроком действия. Секрет подписи хранится только на целевой машине и не входит в репозиторий или bundle.
- Выход аннулирует браузерную cookie. Смена session secret аннулирует все существующие сессии.
- API не принимает пароль через query string и не журналирует пароль, cookie или session secret.
- Встроенный пароль — дополнительный слой к firewall/reverse proxy/bind address, а не замена внешнего периметра.
- Автоматические локальные проверки API на целевой машине могут использовать отдельный служебный bypass только через loopback и явную конфигурацию; внешние клиенты такого bypass не получают.

## Дополнение: первичная настройка через веб-интерфейс

На новой установке `install.sh` генерирует уникальный секрет подписи сессий, но не задаёт пароль за оператора. Пока хэш общего пароля отсутствует, предметные UI/API остаются закрыты, а `/login` показывает одноразовый мастер первого запуска. Первый оператор внутри уже доверенного сетевого периметра задаёт и подтверждает общий пароль; запись хэша выполняется атомарно в SQLite, поэтому из двух одновременных попыток успешно завершиться может только одна. После настройки endpoint первичной инициализации закрывается и дальнейший доступ идёт через обычный общий пароль.

Это trust-on-first-use внутри действующего доверенного контура, а не IAM: пользователей, роли и отдельного администратора приложение не создаёт. До первичной настройки сервер нельзя выставлять в недоверенную сеть; firewall/reverse proxy остаются обязательной внешней границей. CLI `set-password.sh` является запасным локальным интерфейсом к тому же bootstrap API, а не отдельным способом хранения секрета.

## Последствия

ADR-0006 сохраняет модель общего доверенного рабочего пространства и отсутствие IAM, но его решение «без встроенного входа» заменяется этим ADR. `check:no-iam` должен различать запрещённые users/roles/ACL и разрешённый общий password gate.

Установка должна создавать уникальный session secret и требовать явной настройки пароля перед доступом из сети. Обновление не изменяет существующий пароль и session secret.

Все новые предметные API и экспорт данных автоматически наследуют общий password gate.
