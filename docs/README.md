# Документация Docomator

Документация разделена на действующие руководства/контракты и исторические материалы. В рабочий индекс не включаются одноразовые планы аудита, временные маркеры и документы со статусом «будет удалён».

## Быстрый вход

| Документ | Назначение |
|---|---|
| [QUICK_START.md](QUICK_START.md) | короткий рабочий путь, простая установка и обновление |
| [USER_GUIDE.md](USER_GUIDE.md) | полный порядок работы: данные, шаблоны, выпуск, расписания, доставка и диагностика |
| [USE_CASES.md](USE_CASES.md) | практические кейсы и выбор правильного рабочего потока |
| [OFFLINE_DEPLOYMENT.md](OFFLINE_DEPLOYMENT.md) | подробная подготовка автономного комплекта, установка, обновление и откат |
| [VERSIONING.md](VERSIONING.md) | единый источник версии продукта и identity конкретной сборки |

Руководство оператора также доступно непосредственно в веб-интерфейсе через пункт **«Помощь»**. Встроенная документация не требует доступа в Интернет.

При конфликте документов действует следующий приоритет:

1. `docs/REQUIREMENTS.md`;
2. принятые ADR;
3. `docs/ARCHITECTURE.md`;
4. `docs/IMPLEMENTATION_PLAN.md`;
5. `docs/ROADMAP.md`;
6. `README.md`.

Исторические аудиты могут сохраняться как доказательная база, но не определяют текущее поведение системы, если их вывод уже перенесён в нормативные документы и тесты.
