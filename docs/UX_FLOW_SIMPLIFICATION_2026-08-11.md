# Упрощение пользовательских сценариев — 2026-08-11

Статус: реализовано в ветке, требует CI и последующей ручной P5-приёмки.

Связанные требования: UX-001—004, UX-013—014, UX-023, UX-026, UX-032—036, UX-AC-001, DOC-003, TPL-001—030, DATA-001—014.

## Принцип

Оператор не должен нажимать кнопку только для того, чтобы система выполнила безопасное чтение или анализ уже выбранных данных.

Применяется единое правило:

1. **Чтение, локальная/серверная проверка и preview запускаются автоматически**, когда для операции уже достаточно входных данных.
2. **Неоднозначное решение требует участия оператора**: выбор сопоставления, уровня, поля, исправления или режима.
3. **Mutation остаётся явной**: сохранение файла в разделе, импорт строк, изменение карточек, активация шаблона, запуск выпуска, отправка, удаление и административные операции не выполняются автоматически.
4. После ошибки введённые данные и выбранный файл сохраняются, насколько это допускает браузер; рядом остаётся одно понятное действие повторения.
5. Автоматическая операция всегда показывает текущее состояние и не скрывает, что именно делает система.

## Изменённые сценарии

### Подключение DOCX/XLSX-шаблона

Было:

`выбрать файл → нажать «Проверить файл» → увидеть результат → сохранить исходник → нажать «Построить структуру» → выбирать поля`

Стало:

`выбрать или перетащить файл → автоматическая проверка → результат/preview → сохранить исходник → автоматическое построение структуры → выбирать поля`

Кнопки «Проверить сейчас» и «Построить сейчас» остаются вторичными действиями для немедленного запуска или recovery. Они больше не являются обязательными этапами основного пути.

Проверка и построение структуры не изменяют исходный документ и не присваивают ownership. Сохранение исходника в текущем разделе остаётся отдельной явной mutation.

### Импорт CSV/XLSX

Было:

`выбрать/перетащить файл → нажать «Прочитать файл» → колонки → сопоставление → проверка → импорт`

Стало:

`выбрать/перетащить файл → автоматическое чтение колонок → сопоставление → preview/исправление → явный импорт`

Автоматически выполняется только чтение файла и подготовка сопоставления. Создание новых полей, изменение записей и сам импорт не происходят без явного подтверждения оператора.

### Формирование документов

Первичная кнопка формирования остаётся явным действием. Она может внутри одного намеренного запуска выполнить snapshot и preflight — это часть одной операции, которую пользователь уже запросил.

Исправлен обратный дефект: кнопка «Проверить данные ещё раз» теперь **только перечитывает данные**. Если все обязательные значения заполнены, интерфейс показывает состояние «Данные готовы» и отдельную кнопку «Начать формирование». Повторная проверка больше не запускает выпуск скрытым side effect.

## Что сознательно не автоматизируется

- сохранение принятого DOCX/XLSX в разделе данных;
- создание/изменение полей карточек;
- выполнение CSV/XLSX-импорта;
- сохранение привязок шаблона;
- активация проверенной версии шаблона;
- запуск формирования документов;
- повтор неуспешных единиц выпуска;
- SMTP/network-share доставка;
- создание/изменение расписания;
- удаление результатов и maintenance/database-admin операции.

Причина: эти действия изменяют данные, создают неизменяемые версии или имеют внешние side effects. Автоматизация без явного намерения оператора ухудшила бы предсказуемость и восстановимость.

## Regression coverage

Добавлены проверки, которые закрепляют границу:

- выбор DOCX автоматически приводит к результату проверки без клика по кнопке проверки;
- после явного сохранения исходника структура строится автоматически;
- выбор CSV автоматически приводит к разобранным колонкам;
- helper автоматизации не содержит selectors mutation-кнопок;
- повторный generation preflight не может вызвать `startPreparedGeneration()`.

Старые ручные E2E-сценарии сохраняют совместимость: вторичная кнопка позволяет запустить безопасный этап немедленно, поэтому существующие keyboard/recovery пути не удаляются.

## Acceptance

Изменение считается готовым к merge только после:

- repository/unit/API checks;
- `check:ui` и `check:language`;
- Chromium E2E, включая новые automatic-flow tests;
- 320/768/1440 regression matrix;
- проверки отсутствия horizontal overflow и сохранения keyboard/focus поведения;
- зелёного PR CI.

Это изменение не переводит выпуск из `candidate/pilot` в `stable`. Ручная P5-приёмка двух новых пользователей и внешние Debian/Astra/Office/recovery gates остаются отдельными обязательными критериями.
