# Веб-центр документации

## Назначение

Раздел **Справка** делает проектную и пользовательскую документацию доступной непосредственно в Docomator. Для чтения не требуется интернет, GitHub или отдельный сервер документации.

В веб-центр включаются:

- корневой `README.md`;
- все Markdown-файлы каталога `docs/`, включая вложенные каталоги и ADR;
- дополнительные корневые документы `CHANGELOG.md`, `SECURITY.md` и `CONTRIBUTING.md`, если они присутствуют.

## Возможности пользователя

- поиск по названиям, описаниям, заголовкам и полному тексту;
- навигация по категориям;
- содержание текущего документа;
- внутренние переходы между Markdown-файлами;
- глубокая ссылка на конкретный документ и раздел;
- открытие справки клавишей `F1`;
- копирование ссылки на текущую инструкцию;
- чтение без внешних библиотек и CDN.

## Безопасность отображения

Markdown считается документацией проекта, но всё равно отображается ограниченным безопасным преобразователем.

Поддерживаются:

- заголовки;
- абзацы;
- выделение;
- встроенный код;
- блоки кода;
- списки;
- таблицы;
- цитаты;
- ссылки;
- горизонтальные разделители.

Произвольный HTML не исполняется и выводится как текст. Ссылки с опасными схемами не создаются. Внешние HTTP/HTTPS-ссылки открываются отдельно, внутренние `.md`-ссылки остаются внутри центра документации.

## Как добавить новую инструкцию

1. Создайте файл `.md` в каталоге `docs/`.
2. Начните его с заголовка первого уровня.
3. В первом обычном абзаце кратко опишите назначение: этот текст станет описанием карточки.
4. Используйте относительные ссылки на другие документы.
5. Выполните:

```bash
npm run docs:web:build
npm run docs:web:check
```

6. Запустите общую проверку:

```bash
npm run check
```

7. Зафиксируйте исходный Markdown и обновлённый файл `apps/api/ui/generated-documentation.js` одним коммитом.

## Почему каталог хранится в репозитории

Docomator рассчитан на автономную установку. Поэтому документация заранее преобразуется в локальный JS-каталог и поставляется вместе с интерфейсом. Во время работы серверу не требуется читать произвольные пути файловой системы или обращаться к внешнему сайту.

## Детерминированная сборка

Сборщик:

1. сортирует пути;
2. нормализует переводы строк;
3. извлекает метаданные;
4. вычисляет контрольную сумму всех исходных документов;
5. формирует стабильный JS-файл без текущей даты и случайных значений.

Команда `docs:web:check` пересобирает каталог в памяти и сравнивает его с сохранённым файлом. Если документация изменена без обновления веб-каталога, CI завершится ошибкой с командой исправления.

## Категории

Категория определяется по пути и назначению документа:

- **Начало работы** — быстрый старт и основное руководство;
- **Работа оператора** — импорт, шаблоны, формирование, расписания;
- **Установка и эксплуатация** — автономное развёртывание, резервное копирование и диагностика;
- **Архитектура и разработка** — архитектура, требования, план реализации;
- **API и интеграция** — описания программных интерфейсов и контрактов;
- **Архитектурные решения** — `docs/adr/`;
- **Прочее** — документы, которые не попали в предыдущие группы.

Категория влияет только на навигацию и не изменяет исходный файл.

## Ссылки и адреса

Адрес имеет вид:

```text
#documentation/<идентификатор-документа>/<идентификатор-раздела>
```

При обновлении страницы выбранный документ открывается снова. Ссылку можно передать другому оператору той же установки.

Не используйте адрес веб-справки как долгосрочный внешний нормативный источник: главным исходником остаётся Markdown-файл в репозитории.

## Проверка после обновления

После установки новой версии:

1. откройте Docomator;
2. нажмите **Справка**;
3. найдите `Быстрый старт`;
4. выполните поиск по слову `паспорт`;
5. откройте `Импорт людей, заполненных полей и списков в Word`;
6. перейдите по внутренней ссылке в руководство оператора;
7. нажмите `F1` из другого раздела;
8. проверьте отображение таблицы и блока кода;
9. выполните жёсткое обновление страницы и убедитесь, что ссылка восстанавливается.

## Типовые проблемы

### Раздел «Справка» отсутствует

Проверьте, что в UI-бандл включены:

- `generated-documentation.js`;
- `documentation-center.js`;
- `documentation-center.css`.

Затем выполните сборку и перезапуск API.

### Новый документ не появился

Запустите `npm run docs:web:build` и зафиксируйте изменённый сгенерированный каталог.

### CI сообщает об устаревшей документации

Выполните:

```bash
npm run docs:web:build
git diff -- apps/api/ui/generated-documentation.js
```

После проверки добавьте файл в тот же коммит, что и Markdown.

### Внутренняя ссылка открывает не тот документ

Используйте относительный путь от текущего файла, например:

```markdown
[Руководство](USER_GUIDE.md)
[Эксплуатация](OPERATIONS.md#резервное-копирование)
```

### Сложный Markdown выглядит проще, чем на GitHub

Веб-центр намеренно поддерживает ограниченное безопасное подмножество Markdown. Смысл инструкции не должен зависеть от встроенного HTML, скриптов или расширений конкретного сайта.
