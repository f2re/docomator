# Учёт научных публикаций

## Назначение

Контур публикаций связывает универсальные объекты Оформлятор в предметную модель научной деятельности:

```text
Научная статья ← авторство → сотрудник или внешний автор
       │
       ├─ ВАК
       ├─ РИНЦ
       ├─ МБД
       ├─ Scopus
       ├─ Web of Science
       └─ ядро РИНЦ
```

Статья хранится один раз независимо от числа соавторов. Поэтому система различает:

- **уникальные публикации** — число разных статей;
- **авторские участия** — число связей «статья — автор».

Например, одна статья двух преподавателей кафедры даёт одну уникальную публикацию и два авторских участия.

## Полностью автономный режим

Контур публикаций работает только с локальной базой Оформлятор и локальными файлами. Он не обращается к Интернету, не отправляет запросы во внешние реестры и не требует ключей ВАК, eLIBRARY, Scopus, Web of Science или других служб.

Данные поступают только из разрешённых автономных источников:

- ручной ввод оператора;
- локальные CSV/XLSX-файлы;
- ранее сохранённые объекты и карточки преподавателей;
- локальные приказы, перечни, выгрузки и подтверждающие документы.

Названия ВАК, РИНЦ, Scopus и других классификаций являются локальными признаками учёта. Оформлятор не проверяет их во внешней системе. Поле «Источник подтверждения» предназначено для понятного локального основания: названия файла, номера приказа, даты перечня, шифра служебной записки или другого внутреннего документа.

В модуле публикаций запрещены внешние сетевые клиенты и абсолютные сетевые адреса. Это ограничение проверяется автоматически в составе `npm test`.

## Быстрое начало

1. Откройте раздел **Публикации**.
2. Нажмите **Создать стандартную структуру**.
3. Добавьте статьи вручную либо импортируйте локальный CSV/XLSX в разделе **Объекты**.
4. Откройте статью в реестре публикаций и закрепите авторов.
5. Подтвердите классификации ВАК, РИНЦ, МБД и другие признаки по локальным документам.
6. На вкладке **Отчёт** задайте год, преподавателя, кафедру и классификацию.
7. Скачайте CSV, зафиксируйте снимок либо передайте состав в мастер создания документов.

Стандартная структура создаёт тип `scientific-publication` и поля:

| Поле | Назначение |
|---|---|
| Год публикации | годовой отбор и группировка |
| Дата публикации | отбор по периоду |
| DOI | устойчивый идентификатор, введённый или импортированный локально |
| EDN | локально введённый или импортированный идентификатор публикации |
| Журнал или сборник | издание |
| ISSN или ISBN | идентификатор издания |
| Библиографическое описание | готовая строка для отчёта |
| Статус публикации | подготовка, принята, опубликована |
| Кафедра | подразделение преподавателя |

Существующие типы и поля можно выбрать вручную в настройке реестра.

## Авторы

Авторство хранится в `publication_authorships` как связь многие-ко-многим. Для каждой связи сохраняются:

- статья;
- автор;
- порядок авторов;
- роль: автор, ответственный автор, редактор или переводчик;
- рабочее пространство;
- автор изменения и время.

Статья и автор обязаны принадлежать одному пространству. Перемещение связанных объектов между пространствами блокируется до удаления связей.

Внутренним автором считается объект настроенного типа преподавателя. Другой тип объекта можно использовать для внешних соавторов. Термин «внешний автор» означает автора вне штатного списка преподавателей, а не получение его данных через Интернет.

## Классификация

Поддерживаются коды:

| Код | Название |
|---|---|
| `vak` | ВАК |
| `rinc` | РИНЦ |
| `mbd` | МБД |
| `scopus` | Scopus |
| `web_of_science` | Web of Science |
| `rinc_core` | ядро РИНЦ |

Для каждого локального признака хранится состояние:

- **подтверждено** — входит в обычные отчёты;
- **требует проверки** — учитывается только при явном включении;
- **исключено** — запись сохраняется и журналируется, но не входит в отчёт.

Дополнительно сохраняются локальный источник подтверждения, дата проверки и комментарий. Проверку выполняет оператор по доступным внутренним материалам; сетевого подтверждения модуль не производит.

## Поля для шаблонов

После изменения авторов или классификаций реестр обновляет производные поля статьи:

| Техническое поле | Значение |
|---|---|
| `publication.authors` | все авторы через точку с запятой |
| `publication.internal_authors` | только преподаватели |
| `publication.departments` | кафедры внутренних авторов |
| `publication.classifications` | перечень классификаций |
| `publication.vak` | подтверждённый признак ВАК |
| `publication.rinc` | подтверждённый признак РИНЦ |
| `publication.mbd` | подтверждённый признак МБД |
| `publication.scopus` | подтверждённый признак Scopus |
| `publication.web_of_science` | подтверждённый признак Web of Science |
| `publication.rinc_core` | подтверждённый признак ядра РИНЦ |

Эти значения доступны обычным DOCX/XLSX-шаблонам. Поэтому действующий механизм повторяемой строки может сформировать реестр статей без отдельного формата шаблона.

Производные поля помечены как системные. Ручная запись и массовый импорт значений в них блокируются на уровне базы; они изменяются только вместе со связями авторства и классификацией.

## Отчёты

Отчёт поддерживает условия:

- год;
- период публикации;
- одна или несколько классификаций;
- режим «любая» или «все» классификации;
- включение признаков, требующих проверки;
- конкретный преподаватель;
- кафедра;
- статус публикации;
- включение неактивных и архивных статей.

Итоги включают:

- уникальные публикации;
- авторские участия;
- внутренние авторские участия;
- число уникальных преподавателей;
- ВАК, РИНЦ, МБД, Scopus, Web of Science и ядро РИНЦ;
- публикации без DOI;
- публикации без внутренних авторов.

## Формирование документов

Кнопка **Передать в создание документов** создаёт неизменяемый состав типа «Научная статья» из результатов отчёта. Далее используется штатный локальный мастер выпуска документов.

Пример полей повторяемой строки:

```text
subject.position
subject.display_name
publication.year
publication.authors
publication.departments
publication.journal
publication.doi
publication.classifications
```

Для персональной карточки преподавателя задайте преподавателя в фильтре отчёта, создайте состав и используйте шаблон списка публикаций.

## Неизменяемые снимки

Снимок отчёта хранит:

- точные условия выборки;
- итоговые показатели;
- упорядоченные строки;
- автора и идентификатор операции;
- время создания.

Строки и итоги снимка нельзя изменить. Последующее редактирование статьи или авторства не переписывает зафиксированный годовой отчёт. CSV можно скачать непосредственно из снимка, а состав для документа — создать по сохранённому перечню публикаций.

## HTTP API локального сервера

Маршруты обслуживаются тем же локальным сервером Оформлятор. Они не являются внешним API и не инициируют сетевые обращения за пределы установленного контура.

```text
GET  /api/v1/spaces/:spaceId/publications/config
PUT  /api/v1/spaces/:spaceId/publications/config
POST /api/v1/spaces/:spaceId/publications/bootstrap

GET  /api/v1/spaces/:spaceId/publications/:publicationId/authors
PUT  /api/v1/spaces/:spaceId/publications/:publicationId/authors

GET    /api/v1/spaces/:spaceId/publications/:publicationId/classifications
PUT    /api/v1/spaces/:spaceId/publications/:publicationId/classifications/:code
DELETE /api/v1/spaces/:spaceId/publications/:publicationId/classifications/:code

GET  /api/v1/spaces/:spaceId/publications/reports/preview
GET  /api/v1/spaces/:spaceId/publications/reports/export.csv
POST /api/v1/spaces/:spaceId/publications/reports/snapshots
GET  /api/v1/spaces/:spaceId/publications/reports/snapshots
GET  /api/v1/spaces/:spaceId/publications/reports/snapshots/:snapshotId
GET  /api/v1/spaces/:spaceId/publications/reports/snapshots/:snapshotId/export.csv
POST /api/v1/spaces/:spaceId/publications/reports/snapshots/:snapshotId/audience-snapshot
POST /api/v1/spaces/:spaceId/publications/reports/audience-snapshot
```

## Ограничения текущей итерации

- за один отчёт и один состав документов передаётся до 1000 публикаций;
- автоматическое распознавание авторов из одной текстовой колонки импорта ещё не выполняется;
- обращения к внешним реестрам отсутствуют намеренно и не входят в план автономного контура;
- сложные вложенные циклы «преподаватели → их статьи» в одном DOCX не добавлены: персональная карточка формируется выборкой по одному преподавателю;
- снимок отчёта фиксирует строки и точный состав статей, однако штатный генератор документов при запуске читает актуальные значения полей статьи. Для полностью неизменяемого архива используйте CSV снимка либо запускайте выпуск до последующего редактирования данных.

Следующая итерация импорта должна сопоставлять авторов только по сведениям из локального файла и локальной базы: табельному номеру, внутреннему идентификатору, полному или сокращённому ФИО и, при наличии в исходном файле, ORCID. Никаких запросов по этим идентификаторам во внешние службы выполнять не следует.
