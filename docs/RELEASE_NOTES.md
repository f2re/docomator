# Оформлятор 0.6.2

Текущая версия: `0.6.2`.

Статус выпуска: `candidate`

Канал выпуска: `pilot`

Статус: **кандидат на стабильный выпуск**. Номер версии описывает состав продукта и не означает завершение эксплуатационной приёмки. До успешных целевых актов Debian/Astra Linux, восстановления резервной копии, реального Office-корпуса и P5-приёмки выпуск разрешён только для контролируемого пилота на обезличенных данных.

Единственный машинный источник версии, статуса и канала — `RELEASE_IDENTITY.json`.

## 2026-08-21 — общий 4-значный код доступа (`0.6.2`)

- Убрана ложная модель учётной записи: основной экран доступа содержит только один общий код из четырёх цифр. Логин, отдельный пароль и поле подтверждения не используются.
- Приложение не инициирует HTTP Basic Auth и не отправляет `WWW-Authenticate`; встроенный UI не может сам вызвать нативное окно браузера «логин + пароль».
- Первый запуск позволяет задать код прямо в браузере и сразу открыть приложение. Код хранится только как scrypt-хэш; signed session cookie, `SameSite=Strict`, HTTPS `Secure`, same-origin mutation check и локальный backoff сохранены.
- На экране входа появился вторичный пункт «Не помню код» с гарантированно установленной recovery-командой `sudo /opt/docomator/current/first-run.sh --reset-code`. Старый код не нужен; документы, пространства, шаблоны и пользовательские настройки не меняются, прежние браузерные сессии завершаются.
- Для безопасного update/rollback сохранены внутренние legacy-имена таблицы и `DOCOMATOR_ACCESS_PASSWORD_HASH`; новый предпочтительный ключ — `DOCOMATOR_ACCESS_CODE_HASH`. Если на старой установке был обычный длинный пароль, оператор один раз назначает новый 4-значный код через recovery без миграции пользовательских данных.
- Модель доверенного корпоративного контура и отсутствие IAM/ролей не изменены. Четырёхзначный код является только дополнительным барьером от случайного доступа и не заменяет firewall/reverse proxy/HTTPS.

## 2026-08-21 — форматированное визуальное представление DOCX/XLSX (`0.6.0`)

- Мастер шаблона читает локальную безопасную visual-layout проекцию сохранённого DOCX/XLSX: шрифты, размеры, жирный/курсив/подчёркивание, цвета, выравнивание и отступы, таблицы и объединения, размеры строк/колонок, колонтитулы и поддерживаемые raster-изображения.
- Для XLSX добавлена похожая на Excel/Calc сетка с вкладками листов, заголовками строк/колонок, сохранённым отображаемым значением формул и выбором обычных ячеек. Формульная ячейка по-прежнему не может стать полем шаблона.
- Для DOCX основной текст, таблицы, верхние/нижние колонтитулы и сноски используют прежние серверные координаты. Выделение текста остаётся `elementId + UTF-16 offsets`; браузерный DOM не становится источником документа.
- Rich-проекция ограничивает тяжёлые/разреженные таблицы и крупные merge-range до безопасного браузерного представления; недоступные места остаются в резервном списке структуры.
- Динамическое оформление отдаётся отдельным same-origin CSS endpoint с `Cache-Control: private, no-store`; глобальный CSP остаётся `style-src 'self'` без `unsafe-inline`. CSS формируется только из allowlist свойств и диапазонов.
- Внешние relationship target, HTML, макросы, OLE и неизвестные media-типы не исполняются. Поддерживаемые локальные PNG/JPEG/GIF/WebP могут быть показаны как `data:` после действующих размерных ограничений intake.
- Детеминированные renderer/compile/render/reverse-read, модель данных, миграции и граница пространств не изменены. Точная пагинация Word/Calc и сложные DrawingML/SmartArt/OLE подтверждаются пробной копией/PDF и Office-корпусом.
- Новые E2E/regression tests в это изменение не добавлялись по решению владельца; существующий CI остаётся обязательным gate для merge.

## 2026-08-21 — исправление reflow и семантики элементов управления (`0.5.3`)

- Экран входа и одноразовый «Первый запуск» больше не расширяют страницу на узких экранах и при увеличенном тексте.
- Пробное заполнение шаблона получило shrink-safe контейнеры и корректный перенос длинных значений.
- В импорте произвольных объектов внешний drag-and-drop контейнер больше не объявляется отдельной кнопкой поверх нативного `input[type=file]`.

## 2026-08-21 — исправление импорта и первого запуска (`0.5.2`)

- Составные значения с запятыми и точками с запятой больше не угадываются как одиночный enum.
- Для безопасных `invalid_number`/`invalid_integer` при создании нового поля интерфейс предлагает переключить поле на текст и повторить preview без повторной загрузки.
- Структурированные ошибки сохраняют строку, колонку, исходное значение и действие; preview и настройки не теряются.

## 2026-08-18 — упрощение навигации (`0.5.1`)

- На первом уровне навигации оставлены регулярные пользовательские задачи; редкие разделы перенесены в «Управление».
- Recovery-действия сделаны визуально вторичными без изменения модели данных, API и renderer.

## 2026-08-17 — визуальная разметка DOCX (`0.5.0`)

- Основной текст, колонтитулы, сноски и обычные таблицы отображаются в безопасной документоподобной проекции.
- Пользователь может выбрать абзац/ячейку или выделить заменяемый фрагмент; координата проверяется сервером.

## Ранее реализованный базовый контур

Линия `0.1.x—0.4.x` сформировала жёсткую изоляцию пространств, typed properties, guided CSV/XLSX import/export, безопасный DOCX/XLSX intake, детерминированный renderer, scalar/repeat bindings, immutable template releases, worker queue/leases/idempotency, SMTP/network delivery, расписания, общий gate доступа, публичный stateless `/gost`, backup/update/rollback и offline release tooling.

## Что ещё блокирует `stable`

До смены `RELEASE_IDENTITY.json` на `status=stable`, `channel=production` обязательны фактические целевые доказательства: чистая offline-установка Debian и Astra Linux 1.7; реальный LibreOffice; Office-корпус не менее 20 DOCX и 20 XLSX; нагрузка импорта/выпуска 10/100/1000; restart/retry без дублей; backup/restore; update/rollback без потери данных; ручная P5/accessibility-приёмка; пустой список блокирующих дефектов и успешный release-evidence для одного точного commit/version/status.

Точный протокол находится в `docs/FINALIZATION.md`, `docs/SUPPORT_MATRIX.md`, `docs/UX_ACCEPTANCE_PROTOCOL.md` и открытых задачах внешней приёмки.
