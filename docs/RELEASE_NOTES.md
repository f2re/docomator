# Docomator 0.1.0

Статус: **текущая версия продукта**. Функциональный контур реализован, но конкретные сочетания Debian/Astra Linux/LibreOffice/Microsoft Office считаются подтверждёнными только после фактических актов в [`SUPPORT_MATRIX.md`](SUPPORT_MATRIX.md).

`VERSION=0.1.0` не означает, что каждую новую сборку необходимо переименовывать. Номер версии продукта и identity автономной сборки разделены; подробности — [`VERSIONING.md`](VERSIONING.md).

## 2026-08-07 — ревизия интерфейса, обновления и эксплуатационных контрактов

- Обновление больше не блокируется совпадением `VERSION`: конкретная сборка определяется SHA-256 `release.json` и получает отдельный immutable release-каталог.
- Точная повторная установка той же сборки остаётся идемпотентной.
- Обычный install/update можно запускать из распакованного пользовательского каталога; `root:root`-проверка исходного пути стала явным opt-in режимом `DOCOMATOR_STRICT_BUNDLE_PATH=1`.
- Корневой `VERSION` закреплён как единственный вручную изменяемый источник версии; `npm run version:sync` синхронизирует производные значения.
- Добавлен layout regression contract: отсутствие page-level overflow, ограничение progress/range, viewport-safe диалоги/drawers, проверки на 320/768/1440 px.
- Актуализированы root/scope `AGENTS.md` и специализированные Codex-agent инструкции.
- Удалены завершённый audit-remediation plan, WIP-маркер документации и временные import-audit маркеры.
- `QUICK_START.md`, автономное развёртывание и корневой README приведены к фактическому рабочему процессу.
- Документация пространств приведена к жёсткой изоляции сущностей, пользовательских полей, групп, шаблонов и связанных результатов.

## 2026-08-07 — изоляция данных по пространствам

- Сущности и их значения не разрешаются через чужой `spaceId`.
- Определения пользовательских полей независимы между пространствами; одинаковые названия допустимы и не создают общей записи.
- БД отклоняет запись значения с определением поля другого пространства.
- Поля и конфигурация научных публикаций изолированы по пространствам.
- Группы, снимки состава, черновики и версии шаблонов проходят cross-space проверки.
- Legacy-поля без владельца допускают только контролируемое закрепление за пространством совместимой внутренней операцией.

## 2026-07-31 — единая актуальная реализация UI

- Удалены параллельные `v2`, `v3` и recovery-модули импорта, расписаний, групп, многополевой проверки и редактора повторяемой строки.
- Последняя функциональность перенесена в канонические файлы; CI запрещает возврат параллельных реализаций.
- CSV/XLSX-импорт сохраняет координаты пустых ячеек, физические номера строк, нормализацию регистра и поддержку ФИО.
- Веб-панель SQLite получила безопасный поиск, просмотр, экспорт и создание логических полей без произвольного SQL.
- Generic offline bundle собирается и проверяется в CI; целевые Debian/Astra bundles требуют соответствующих стендов.

## 2026-07-30 — укрепление репозитория и интеграционного контура

- Удалены одноразовые workflow, применявшие закодированные патчи или запись по комментарию issue.
- `check:audit` запрещает возврат самоприменяющихся workflow, устаревшей справки и скрытой регистрации маршрутов.
- Политика безопасности фиксирует отсутствие встроенной аутентификации и обязательный внешний доверенный периметр.
- OOXML-шлюз ограничивает фактический размер частей и всего распакованного потока.
- CI запускает реальные API/worker проверки, а Chromium real-stack smoke подтверждает сохранение в SQLite и перезагрузку.

## 2026-07-30 — координатный импорт и администрирование БД

- XLSX читается по координатам: отсутствующие и самозакрывающиеся пустые ячейки не сдвигают данные.
- CSV/XLSX сохраняют физические номера строк и переносы внутри ячеек.
- Добавлены сравнение без учёта регистра, нормализация ФИО и разбор фамилии/имени/отчества.
- Повторный импорт не создаёт дубликаты при различии только регистра.
- Управление БД поддерживает проверяемый просмотр, сортировку, CSV/JSON-экспорт и логические поля.

## 2026-07-28 — произвольные объекты и автономная поставка

- Пространства поддерживают людей, аудитории, публикации, оборудование и другие типы объектов.
- Добавлены каталог объектов, ручное редактирование, гибкий CSV/XLSX-импорт и предварительный план без записи.
- Редактор шаблона и выпуск фильтруют доступные данные по типу/пространству.
- Автономный сборщик формирует проверяемое замыкание системных пакетов и точный manifest bundle.

## 2026-07-26 — шаблоны, progress и CSP

- Повторяемые строки DOCX остаются непосредственными строками исходной таблицы и не отделяются от заголовка служебным контейнером.
- PDF-предпросмотр сделан отдельной необязательной проверкой перед активацией.
- Полосы выполнения используют нативный `<progress>`; встроенные стили удалены, CSP проверяется в CI.
- Исправлена визуальная иерархия основного рабочего пути, центр операций и мобильная помощь.

## Миграции и откат

Миграции SQLite добавляются только новыми файлами и защищены контрольными суммами. Уже применённая миграция не редактируется.

При обновлении:

1. создаётся резервная копия конфигурации и SQLite;
2. новая сборка устанавливается в отдельный immutable-каталог;
3. выполняются миграции;
4. атомарно переключается `/opt/docomator/current`;
5. проверяется readiness;
6. при ошибке возвращаются прежняя сборка, БД и конфигурация.

## Проверки выпуска

Обязательная автоматическая база:

```bash
npm run check
```

Целевая эксплуатационная приёмка дополнительно требует фактических Debian/Astra/LibreOffice прогонов, восстановления резервной копии и реального Office-корпуса по [`FINALIZATION.md`](FINALIZATION.md).
