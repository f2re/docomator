# Оформлятор 0.5.1

Текущая версия: `0.5.1`.

Статус выпуска: `candidate`

Канал выпуска: `pilot`

Статус: **кандидат на стабильный выпуск**. Номер `0.5.1` обозначает текущий набор возможностей продукта, но не означает завершение эксплуатационной приёмки. До успешных целевых актов Debian/Astra Linux, восстановления резервной копии, реального Office-корпуса и P5-приёмки выпуск разрешён только для контролируемого пилота на обезличенных данных.

Единственный машинный источник версии, статуса и канала — `RELEASE_IDENTITY.json`. `VERSION`, package metadata, lockfile, runtime defaults и текущие выпускные документы проверяются относительно него в CI.

## 2026-08-18 — упрощение навигации и автоматических шагов

- Desktop-навигация оставляет на первом уровне только ежедневные задачи: Главная, Сотрудники, Шаблоны, Создать документы, Результаты, Расписания и Управление.
- Редкие предметные разделы — Объекты и импорт, Публикации, Форматирование по ГОСТ и Руководство — доступны через Управление; динамически подключаемый модуль больше не раздувает основной список навигации.
- Дублирующая плитка Расписаний удаляется из Управления, если этот раздел уже присутствует на первом уровне.
- Автоматическая безопасная проверка шаблона и другие recovery-действия не выглядят обязательными primary-кнопками даже до разблокировки; ручной повтор подписан как «Проверить сейчас».
- Технический перечень проверок DOCX/XLSX свёрнут под «Что проверяется», при этом ошибки и конкретные действия по исправлению остаются в основном потоке.
- Добавлены Chromium regression-тесты на семь desktop-разделов, перенос secondary-модулей в Управление, отсутствие дублирующего действия и корректную иерархию автоматической проверки.
- Полный аудит интерфейса и пользовательских задач зафиксирован в `UX_AUDIT_2026-08-18.md`; модель данных, API, renderer и границы безопасности не менялись.
- Изменение оформлено как обратно совместимый UI/regression patch: `0.5.0 → 0.5.1`; статус остаётся `candidate / pilot`.

## 2026-08-17 — визуальная разметка полей DOCX

- На шаге разметки DOCX основной интерфейс больше не сводит структуру к списку абзацев: основной текст, верхние и нижние колонтитулы, сноски и обычные таблицы собираются в безопасную документоподобную проекцию.
- Текст каждого `w:r` выводится только как экранированные данные; существующие признаки жирного и курсива отображаются визуально, но HTML не становится источником Office-документа.
- Пользователь может нажать целый абзац/ячейку либо выделить изменяемый фрагмент непосредственно на странице. DOM-выделение преобразуется в существующие `elementId + UTF-16 offsets`, после чего backend выполняет прежнюю проверку SHA/структуры и компилирует `w:sdt`.
- Существующий инспектор поля, типизированные источники, форматтеры, repeat-row, reverse-read и production renderer не заменены новым механизмом.
- Для клавиатуры и сложной верстки сохранён раскрываемый резервный список мест документа; `Enter`/`Space` открывают тот же инспектор, минимальная зона выбора остаётся 44 CSS px.
- На узком экране инспектор переносится под документ, а таблицы получают внутреннюю прокрутку без глобального горизонтального overflow.
- Интерфейс прямо сообщает, что браузерная поверхность не является пиксельно идентичным Word layout: точные переносы страниц, рисунки и сложные Office-объекты подтверждаются пробной копией и PDF-предпросмотром LibreOffice.
- XLSX в этом приращении намеренно остаётся на существующем проверенном cell-view; изображения/DrawingML пока показываются только через итоговый Office/PDF-контроль и не объявлены новыми заменяемыми объектами.
- Добавлен Chromium regression на прямое выделение `ФИО: ______ → offsets 5..11`, таблицу 2×4, клавиатуру, 320 px и сохранение прежнего XLSX-flow.
- Новая обратно совместимая пользовательская возможность повышает версию `0.4.0 → 0.5.0`; статус остаётся `candidate / pilot`.

## 2026-08-12 — ГОСТ/ЕСКД, библиография и публичное форматирование

- Реально подключён production-контур «Публикации»: существовавшие API/UI больше не остаются мёртвым модулем вне штатного bootstrap.
- В разделе публикаций добавлен офлайн-обмен BibTeX и CSL JSON для Zotero и других менеджеров: предпросмотр, структурированные ошибки, проверка дублей, импорт новых записей и обратный экспорт без обязательной облачной синхронизации.
- Внешний библиографический автор не превращается автоматически в сотрудника; связь с сотрудником создаётся только при однозначном совпадении внутри текущего пространства.
- Добавлен отдельный пользовательский раздел **«Форматирование по ГОСТ»** с профилями ГОСТ Р 7.0.97-2025 и ЕСКД ГОСТ Р 2.105-2019, drag-and-drop нескольких DOCX, едиными настройками пакета, частичным успехом и повтором только ошибочных файлов.
- Авторизованный пакетный режим использует space-scoped quarantine, SQLite job state и существующий worker; исходные DOCX не перезаписываются.
- Детерминированный formatter меняет только базовые свойства стилей/страницы и повторно валидирует OOXML-пакет; формулы, таблицы, изображения, колонтитулы и неизвестные части не генерируются ИИ и не должны перекодироваться.
- Для пользователей без входа добавлен `/gost`: stateless-анализ и форматирование одного HTTP-файла за запрос без `spaceId`, SQLite, object store, worker queue, LLM, LibreOffice и сохранения документа. Обычные пространства и сохраняемые API остаются за password gate.
- Публичный formatter ограничен размером входа и числом одновременно выполняемых операций; regression test одновременно проверяет доступ `/gost` без cookie и `401` для обычного space API.
- Искусственный минимум общего пароля 12 символов удалён во всех слоях. Пароль должен быть непустым, технический максимум — 512 Unicode-символов. Добавлен явный `reset-password.sh`, который ротирует session secret и не меняет пользовательские данные.
- Базовые checkbox/radio приведены к компактному индикатору 18 px при сохранении 44 px интерактивной строки.
- Добавлены regression tests на space isolation batch-formatting, OOXML preservation, BibTeX/CSL round-trip, короткий пароль, production bootstrap и публичный ГОСТ без авторизации.
- Изменение оформлено как новая обратно совместимая продуктовая возможность: `0.3.1 → 0.4.0`; статус остаётся `candidate / pilot`.

## 2026-08-12 — адресные ошибки импорта и частичная обработка

- Устранена потеря машинного контракта ошибок на пути parser → API → UI: файловые и сопоставительные ошибки теперь несут стабильные `code`, `scope`, `blockingEffect`, `severity`, `suggestedAction` и параметры исправления; row/cell ошибки дополнены областью и минимальной блокировкой строки.
- UI больше не восстанавливает колонку и действие regexp-ами из русского текста. Он использует `column`, `propertyKey`, `rawValue`, `repair` и `suggestedAction`, подсвечивает конкретное сопоставление и точную ячейку предварительного просмотра.
- Ошибка одной строки не блокирует корректные строки: после проверки основная кнопка явно импортирует только корректные записи, а ошибочные остаются в отчёте с физическим номером строки и исходным значением.
- Ошибка сопоставления не сбрасывает выбранный файл, назначение колонок и введённые настройки; оператор исправляет отмеченное поле и повторяет проверку.
- Старый бинарный Excel 97–2003 (`.xls`) определяется отдельно и получает понятное действие «сохранить как XLSX или CSV» вместо общей ошибки разбора. Это не расширяет заявленный формат импорта: поддерживаемыми остаются CSV/XLSX.
- Вставленная одноколоночная таблица из Excel/LibreOffice теперь разбирается как допустимый CSV-предпросмотр, а не отклоняется из-за отсутствия разделителя.
- Добавлены parser/API/Chromium regression tests на legacy XLS, неверный XLSX-контейнер, structured mapping error, raw cell value, физическую строку, подсветку source cell и доступность импорта корректных строк.
- Версия повышена как обратно совместимое исправление основного сценария импорта: `0.3.0 → 0.3.1`; статус остаётся `candidate / pilot`.

## 2026-08-11 — первичная настройка общего пароля в браузере

- Устранён блокирующий дефект offline first-run: интерфейс и `first-run.sh` ссылались на отсутствующий `scripts/offline/set-password.sh`, а installer не создавал session secret.

- После инициализации bootstrap endpoint закрыт; модель остаётся общей для доверенного контура без пользователей, ролей и ACL.
- В offline bundle реально включён `set-password.sh`: он остаётся headless/recovery-способом и поддерживает последующую смену пароля с ротацией сессий.
- Версия повышена как новая обратно совместимая возможность первого запуска: `0.2.1 → 0.3.0`; статус остаётся `candidate / pilot`.

## 2026-08-08 — password gate, экспорт и физическая нормализация legacy-полей

- Оформлятор требует один общий пароль приложения без пользователей, ролей и ACL. На узких экранах действие «Выйти» доступно через «Настройки»; E2E проверяет полный путь `401 → вход → рабочий UI/API → выход → 401` на 320/768/1440 px.
- Добавлен пользовательский CSV/XLSX-экспорт выбранного пространства и типа объектов без UUID и машинных ключей; XLSX хранит пользовательские строки как текст и не создаёт вычисляемые формулы из входных значений.
- Новая additive migration `0030_normalize_legacy_shared_properties.sql` устраняет историческое исключение до `0027`: определение, которым уже владело несколько пространств, физически клонируется отдельно для каждого пространства, а его значения перепривязываются к соответствующему clone.
- Старый ключ общего поля после `0030` сохраняется только как `space_property_definition_aliases` внутри того пространства, где поле исторически использовалось. Это позволяет неизменяемым активированным шаблонам и сохранённым импортным сопоставлениям разрешить старый ключ, не возвращая общий mutable-ресурс.
- Переходный `claim-on-first-write`, возвращённый миграцией `0029`, удалён. После `0030` запись значения допускается только для определения с заранее и явно установленным владельцем пространства; чтение, preview и запись больше не назначают ownership побочным эффектом.
- Employee, publication, import, preflight и worker generation используют space-aware compatibility-слой: alias соседнего пространства не разрешается, а старый шаблон получает значение только из physical clone своего пространства.
- Добавлен upgrade regression `pre-0027 shared A/B → 0027/0028/0029/0030`: после миграции shared-view пуст, A и B имеют независимые определения и значения, пространство C не может принять старый ключ, а raw-запись в unowned property отклоняется SQLite.
- CI теперь запрещает новый повтор numeric prefix миграции; исторический дубль `0026` сохранён как явно перечисленное исключение без переписывания истории.

## 2026-08-07 — изоляция пространств и сопровождаемый импорт

- Legacy API произвольных объектов ограничен детерминированным пространством `default`; чтение, создание и изменение пользовательских объектов через новый контур требуют выбранного пространства.
- Публичная поверхность `@docomator/storage` больше не предоставляет конструкторы глобальных mutable-регистров Knowledge/Employee/Publication; они доступны только через явный internal entrypoint для bootstrap и совместимости.
- `DataImportRegistry` сам использует space-scoped knowledge: импорт одного пространства не может разрешить, создать или изменить пользовательское поле другого пространства.
- Предварительный план импорта не присваивает ownership историческим полям и не имеет побочного `claim-on-read`/`claim-on-plan`.
- Ошибки CSV/XLSX рождаются в storage как машинный контракт: `code`, строка, `column`, `propertyKey`, `rawValue`, `severity`, `suggestedAction` и параметры исправления. HTTP/UI больше не восстанавливают тип ошибки regexp-ами из русского текста.
- Для generic import сохранены drag-and-drop, адресная подсветка проблемного сопоставления, переход к корректирующему control и защита от горизонтального переполнения.
- Добавлены отрицательные тесты с двумя пространствами и одинаковыми названиями полей/объектов, а также проверки legacy API и типизированных ошибок.
- Миграции `0027`/`0028` ввели пространственную принадлежность полей и запрет новых межпространственных связей; оставшееся историческое shared-состояние окончательно нормализуется отдельной новой миграцией `0030`, не изменяя уже применённую историю.

## Что ещё блокирует `stable`

До смены `RELEASE_IDENTITY.json` на `status=stable`, `channel=production` обязательны:

1. чистая offline-установка и target act на Debian;
2. отдельный нативный target act на Astra Linux 1.7;
3. реальный LibreOffice на обоих target без `SKIPPED`;
4. не менее 20 реальных DOCX и 20 XLSX с проверкой LibreOffice и Microsoft Office;
5. импорт и выпуск на 10/100/1000 объектах без смещения, дублей и потери результатов;
6. restart/retry worker без второго результата;
7. backup/restore на отдельном чистом стенде с совпадением SHA-256 объектов;
8. update/rollback без потери данных;
9. два новых пользователя, клавиатура, 200% zoom, 320/768/1440, light/dark и accessibility acceptance;
10. пустой список блокирующих дефектов и успешный `release:evidence` для одного commit/version/status.

Точный протокол находится в `FINALIZATION.md`, `SUPPORT_MATRIX.md` и открытых задачах внешней приёмки.

## Основной поддерживаемый сценарий кандидата

Оператор выбирает пространство, импортирует CSV/XLSX с preview и исправлением ошибок, настраивает DOCX/XLSX-шаблон, выполняет проверку, формирует документы и получает результат. При разметке DOCX пользователь работает с безопасной документоподобной проекцией, но техническая привязка и выпуск по-прежнему проходят только через серверно проверенный детерминированный compiler. Отдельно доступен публичный stateless-сценарий `/gost`, который не использует пространство и не сохраняет документ. Система должна работать без Internet и без LLM; LLM остаётся необязательным помощником и не выполняет shell, SQL, произвольный код, пути или OOXML.

Пространство является жёсткой границей сохраняемых пользовательских данных: сотрудники и другие объекты, группы, пользовательские поля и значения, шаблоны, импортная память, публикации и связанные данные не должны пересекаться между пространствами.

## История версий

Линия `0.1.0` сформировала основной candidate-контур: канонический UI, space isolation, guided CSV/XLSX import, нормализацию ФИО, произвольные типы объектов, безопасный Database Admin, детерминированный DOCX/XLSX renderer, repeat-row, доставку, offline bundle и release-evidence tooling. Начиная с `0.2.0`, номер меняется вместе с изменением продуктового поведения по правилам `VERSIONING.md`.
