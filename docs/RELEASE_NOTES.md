# Оформлятор 0.5.3

Текущая версия: `0.5.3`.

Статус выпуска: `candidate`

Канал выпуска: `pilot`

Статус: **кандидат на стабильный выпуск**. Номер версии описывает состав продукта и не означает завершение эксплуатационной приёмки. До успешных целевых актов Debian/Astra Linux, восстановления резервной копии, реального Office-корпуса и P5-приёмки выпуск разрешён только для контролируемого пилота на обезличенных данных.

Единственный машинный источник версии, статуса и канала — `RELEASE_IDENTITY.json`. `VERSION`, package metadata, lockfile, runtime defaults и текущие выпускные документы синхронизируются с ним.

## 2026-08-21 — исправление reflow и семантики элементов управления

- Экран входа и одноразовый «Первый запуск» больше не расширяют страницу на узких экранах и при увеличенном тексте: сетка, карточка и элементы формы допускают корректное сжатие, а длинные подписи и сообщения переносятся внутри доступной ширины.
- Пробное заполнение шаблона получило shrink-safe контейнеры, корректный перенос длинных значений, ссылок и технических сведений, а одноколоночная компоновка не выталкивает страницу за границы viewport.
- В импорте произвольных объектов внешний контейнер drag-and-drop больше не объявляется отдельной кнопкой поверх нативного `input[type=file]`. Выбор файла мышью и drag-and-drop сохранены, а клавиатурная доступность остаётся у штатного file input без вложенных интерактивных controls.
- Модель безопасности, пространство данных, API импорта, renderer и формат документов не изменялись.
- Исправление обратно совместимо и повышает версию `0.5.2 → 0.5.3`; статус остаётся `candidate / pilot`.

## 2026-08-21 — исправление импорта и первого запуска (`0.5.2`)

- Составные значения с запятыми и точками с запятой больше не угадываются как одиночный enum; варианты явного списка разбираются по строкам и не дробятся внутри пользовательского значения.
- Для безопасных `invalid_number`/`invalid_integer` при создании нового поля интерфейс предлагает переключить поле на текст и повторить предварительную проверку без повторной загрузки файла и без сохранения данных до подтверждения импорта.
- Структурированный контракт ошибок сохраняет точную строку, колонку, исходное значение и конкретное действие; preview и настройки не теряются после ошибки.
- Checkbox в мастере импорта имеет компактный индикатор при сохранении доступной интерактивной строки; карточки сопоставления и preview ограничены рабочей областью.
- В интерфейсе отображается фактическая версия запущенного API из `/healthz`; `first-run.sh` показывает короткий пользовательский сценарий вместо внутреннего release-backlog.
- Offline install/update допускает корректно распакованный bundle, принадлежащий root или фактическому пользователю `sudo`, сохраняя fail-closed проверки владельца, прав и manifest.

## 2026-08-18 — упрощение навигации (`0.5.1`)

- На первом уровне desktop-навигации оставлены регулярные пользовательские задачи; редкие предметные разделы перенесены в «Управление».
- Recovery-действия автоматических шагов сделаны визуально вторичными, а технические перечни проверок скрыты под раскрываемыми пояснениями.
- Основной flow стал короче без изменения модели данных, API, renderer и границы безопасности.

## 2026-08-17 — визуальная разметка DOCX (`0.5.0`)

- Основной текст, верхние и нижние колонтитулы, сноски и обычные таблицы отображаются в безопасной документоподобной проекции.
- Пользователь может выбрать абзац/ячейку или выделить заменяемый фрагмент; браузерное выделение преобразуется в существующие серверно проверяемые `elementId + UTF-16 offsets`.
- HTML не становится источником Office-документа. Точная верстка подтверждается пробной копией и PDF-предпросмотром LibreOffice.

## Ранее реализованный базовый контур

Линия `0.1.x—0.4.x` сформировала жёсткую изоляцию пространств, typed properties, guided CSV/XLSX import/export, безопасный DOCX/XLSX intake, детерминированный renderer, scalar/repeat bindings, immutable template releases, worker queue/leases/idempotency, SMTP/network delivery, расписания, общий password gate, публичный stateless `/gost`, backup/update/rollback и offline release tooling. Подробная история каждого изменения сохраняется в истории Git и соответствующих pull request/issues.

## Что ещё блокирует `stable`

До смены `RELEASE_IDENTITY.json` на `status=stable`, `channel=production` обязательны фактические целевые доказательства: чистая offline-установка Debian и Astra Linux 1.7; реальный LibreOffice; Office-корпус не менее 20 DOCX и 20 XLSX; нагрузка импорта/выпуска 10/100/1000; restart/retry без дублей; backup/restore на отдельном стенде; update/rollback без потери данных; ручная P5/accessibility-приёмка; пустой список блокирующих дефектов и успешный release-evidence для одного точного commit/version/status.

Точный протокол находится в `docs/FINALIZATION.md`, `docs/SUPPORT_MATRIX.md`, `docs/UX_ACCEPTANCE_PROTOCOL.md` и открытых задачах внешней приёмки.
