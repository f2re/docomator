# Рабочее место разметки шаблона — 0.7.7

## Решение

Основной объект работы — сохранённый DOCX/XLSX, не отчёт парсера и не набор технических форм. Из вариантов «последовательный мастер», «документ с контекстной панелью» и «реестр операций» выбран второй: пользователь выделяет место в документе, назначает поле и сохраняет рабочий шаблон. Реестр операций остаётся для результатов; техническая пробная копия — дополнительный маршрут.

Обычный путь: **Документ → Разметка → Готово → Создать документы**. Чтение файла запускается после выбора или перетаскивания без синтетического клика и задержки. «Открыть для разметки» явно сохраняет исходник; после подтверждения открывается структура. Повторное открытие использует сохранённый черновик. Ручные команды чтения остаются для повтора после ошибки.

## Поведение редактора

Нативная панель над документом содержит имя файла, раздел данных, назначенные поля, масштаб и сохранение. Выделение открывает инспектор рядом с документом на широком экране; на узком экране и при увеличении текста области располагаются последовательно. Технические счётчики и ограничения проекции вынесены в дополнительные сведения. Предупреждения о реальных ошибках не скрываются.

Список полей и пометки на странице используют подтверждённые `elementId`, а не DOM-координаты. Нажатие назначенного места открывает изменение поля или обязательности и снятие назначения. Параметры типа объектов, формата, повторения строки и точного выделения раскрываются по необходимости. Изменение обязательности не сбрасывает формат ФИО, числа или времени. Снятие назначения не удаляет исходник, карточки или активные версии.

«Сохранить шаблон» использует существующую серверную сборку и обратное чтение. Результат становится активным только после подтверждения сервера. «Создать документы» передаёт идентификатор именно сохранённой версии в каталог текущего пространства; появление другого шаблона первым в списке не меняет выбор.

## Восстановление и границы

Запрос назначения фиксирует исходное пространство, черновик, элемент и выделение. Поздний ответ не возвращает данные другого пространства. Повтор снятия после потерянного ответа сверяется с серверным черновиком. Подтверждённая запись сохраняется в интерфейсе отдельно от успешности последующего чтения. Ошибка оставляет выбор и параметры в форме.

DOM, CSS и масштаб не записываются в Office. Изменений схемы SQLite, применённых миграций, модели доступа и renderer нет. Проверки ZIP/XML, хеша исходника, пространства и точности подстановок остаются в backend. Статус `candidate / pilot` не означает подтверждение произвольного DOCX или целевую приёмку Debian/Astra.

## Проверка

`studio-workbench.spec.mjs` проверяет DOCX/XLSX, панель инструментов, пометки, изменение и снятие назначения, повтор после ошибки, позднее чтение другого пространства, точный переход к выпуску, клавиатуру, темы, увеличение текста и отсутствие временной блокировки следующего щелчка.

Существующая браузерная матрица открывает дополнительные параметры явным действием пользователя. Реальный сценарий `real-stack-document-flow.spec.mjs` дополнительно меняет назначение через API перед сохранением, формирует DOCX с повтором и сверяет скачанные значения и нетронутые части пакета.

Итоги конкретного запуска, хеш дерева, PR и CI фиксируются в подтверждённом протоколе PR. Предыдущие неподтверждённые числа тестов 0.7.7 не являются свидетельством этой реализации. Связанные задачи: #154, #158. Целевая и ручная приёмка остаются отдельными задачами.
